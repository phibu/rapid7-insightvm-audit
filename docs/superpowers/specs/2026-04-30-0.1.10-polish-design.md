## Summary

Quality-and-docs patch that polishes 0.1.9. Tightens user-audit rule documentation links to deep anchors on `docs.rapid7.com/insightvm/`, fills the gaps surfaced during the 0.1.9 final review (print CSS doesn't expand `<details>`, `_metrics` lacks a `rules_error` bucket, `_compute_delta` ignores operational-check findings, unidiomatic import aliases), and documents the embedded state-blob convention in CLAUDE.md.

Seven items in five commits, ~130 LOC across ~13 files. Single PR. No interactivity, no Phase 2 work.

## Goals

1. Make every finding's source link land on a useful Rapid7 doc page (deep anchor when clear, page-level URL otherwise — never a 404).
2. Fix the 0.1.9 follow-ups so that the metric grid is internally consistent (`rules_total` matches the sum of severity buckets), the delta strip covers all findings, and printed reports actually show finding details.
3. Document the cross-run state-blob convention so a future contributor doesn't accidentally remove the embedded JSON blob thinking it's dead code.

## Non-Goals

- No new features.
- No Phase 2 interactivity (filter bar, theme toggle, JS rule-card toggle, a11y test sweep) — those land in 0.2.0.
- No tech-debt sweep (validator dedup, endpoint-404 self-skip test, dead-comment cleanup) — deferred to 0.1.11 or rolled into 0.2.0.
- No changes to data model, HTTP client, or audit/snapshot layer.

### Item 4 — `_compute_delta` includes operational-check findings

**Files:** `src/rapid7_healthcheck/report.py`, `tests/test_report_delta.py`.

In `_compute_delta`'s `index()` helper, add a second loop that walks `r.get("findings", [])` keyed by check name:

```python
def index(state: dict) -> dict[str, dict]:
    out: dict[str, dict] = {}
    for r in state.get("results", []):
        check_name = r.get("name")
        # Audit-rule findings.
        for rr in r.get("rule_results", []) or []:
            rule_id = rr.get("rule_id")
            for f in rr.get("findings", []):
                sig = f.get("signature")
                if sig:
                    out[sig] = {**f, "rule_id": rule_id}
        # Operational-check top-level findings (use check_name as namespace).
        for f in r.get("findings", []) or []:
            sig = f.get("signature")
            if sig:
                out[sig] = {**f, "rule_id": check_name}
    return out
```

The state-blob projection (from 0.1.9 Task 4) already emits signatures for top-level findings using the check name as the namespace — this hooks in with no projection change.

**Tests** (`tests/test_report_delta.py`): add 2 cases reusing the existing `_state` / `_check` / `_f` helpers:

```python
def test_compute_delta_includes_operational_check_resolved():
    """A scan-engine warning that disappears between runs counts as resolved."""
    prior = _state([{"name": "Scan Engines", "status": "warn", "duration_ms": 100,
                     "findings": [_f("op_a", severity="warn")], "rule_results": []}])
    cur = _state([{"name": "Scan Engines", "status": "pass", "duration_ms": 100,
                   "findings": [], "rule_results": []}])
    delta = _compute_delta(prior=prior, current=cur)
    assert len(delta["resolved"]) == 1
    assert delta["resolved"][0]["signature"] == "op_a"


def test_compute_delta_operational_check_new_fail():
    """A new fail-severity finding in an operational check shows up in new_fails."""
    prior = _state([{"name": "Scan Engines", "status": "pass", "duration_ms": 100,
                     "findings": [], "rule_results": []}])
    cur = _state([{"name": "Scan Engines", "status": "fail", "duration_ms": 100,
                   "findings": [_f("op_b", severity="fail")], "rule_results": []}])
    delta = _compute_delta(prior=prior, current=cur)
    assert len(delta["new_fails"]) == 1
    assert delta["new_fails"][0]["signature"] == "op_b"
```

**Acceptance:** `pytest tests/test_report_delta.py -v` green with 16 tests (14 existing + 2 new).

### Item 5 — CLAUDE.md state-blob doc + release

**Files:** `CLAUDE.md`, `CHANGELOG.md`, `pyproject.toml`.

**CLAUDE.md**: in the existing "Report rendering quirk" subsection of `## Architecture`, append a paragraph after the existing one about `_annotate_findings`:

> The 0.1.9 layout embeds a `<script id="report-state" type="application/json">` blob at the end of `<body>`. It is a *trimmed projection* of the run (signatures + severity + short message — never the full `details`), capped at 1 MB by `_state_blob_projection`. The next run's `_load_prior_state` regex-extracts this blob to compute deltas via `_compute_delta`, and the footer's "Run hash" is the SHA-256 prefix of its serialized form. Don't remove the blob thinking it's dead code — it's load-bearing across runs.

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Deep anchor we pick today redirects or 404s in 6 months | Verify HTTP 200 at commit time. Acceptable residual risk — Rapid7 docs are stable enough; same risk as the URLs we have today. |
| Always-render `rules_error` tile shows 0 in the common case, feels like noise | Already the pattern for "Findings · warn" / "Skipped" — those routinely show 0. Visual consistency is the win. |
| `_compute_delta` scope-grow surprises a 0.1.9 user | Behavior strictly grows (no false positives, no findings stop counting). CHANGELOG entry explicitly notes the expanded scope. |
| State-blob doc in CLAUDE.md drifts from code | Same risk as any doc. Mitigation: keep it short enough that updating it is cheap. |

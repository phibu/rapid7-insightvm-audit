## Task-by-task design

### M1 -- `assumed_*_minutes` ≤0 guard

**Files:**
- `src/rapid7_healthcheck/audit/rules/overlapping_scan_windows.py` -- reads `assumed_scan_duration_minutes`
- `src/rapid7_healthcheck/audit/rules/scan_report_schedule_overlap.py` -- reads `assumed_report_duration_minutes` and `assumed_scan_duration_minutes`

**Fix:** Wrap each `int(rule_config.get(...))` cast in `max(1, ...)`. A zero or negative assumed duration would collapse the overlap window to a point in time (silent suppression of findings) or produce a negative `timedelta` (mathematically broken). Non-numeric strings still surface as `status="error"` -- that behavior is intentional ("bad config → error rule" is the project pattern).

**Implementation:** introduce a tiny helper inside each rule (NOT a shared module -- just one local function):

```python
def _positive_minutes(value, default: int) -> int:
    try:
        n = int(value)
    except (TypeError, ValueError):
        return default
    return max(1, n)
```

Or even simpler -- inline `max(1, int(rule_config.get("assumed_scan_duration_minutes", 60)))`. The wrapping `int()` call already raises on non-numeric, which surfaces as error rule. Inline is cleaner.

**Verification (TDD):**
- Test that `assumed_scan_duration_minutes: 0` produces the same output as `assumed_scan_duration_minutes: 1` (sanity floor) -- not "no findings" (which would be the bug).
- Test that `assumed_scan_duration_minutes: -5` also floors to 1.
- Test that `assumed_scan_duration_minutes: "abc"` still raises (becomes error rule) -- preserves the "bad config = error rule" pattern.

### M4 -- Direct unit tests for `is_local_engine`

**Files:** `tests/test_local_engine.py` (new)

**Tests cover:**
- Loopback addresses: `127.0.0.1`, `::1`, `localhost` → True (with various names)
- Default name match (case-insensitive): `"local scan engine"`, `"LOCAL SCAN ENGINE"`, `"Local Scan Engine"` → True
- Whitespace tolerance: `" Local scan engine "` → True
- Non-default, non-loopback → False
- `extra_names={"my-renamed-local"}` → True for that name
- Edge cases: `{}`, `{"name": None, "address": None}`, `{"name": ""}` → False

### F1 -- Ghost Assets rule

**Files:** `src/rapid7_healthcheck/checks/asset_coverage.py` -- new `GhostAssetsRule` class
**Config:**
- `src/rapid7_healthcheck/config.py` -- new `AssetCoverageThresholds.flag_ghost_assets: bool = True`
- `docs/examples/config.yaml` -- add the key with inline comment

**Rule definition:**
```python
class GhostAssetsRule:
    RULE_ID = "op.asset_coverage.ghost_assets"
    RULE_NAME = "Assets with no OS fingerprint AND no hostName (ghost records)"
    DESCRIPTION = (
        "Assets the console knows about but cannot identify -- neither an OS "
        "fingerprint nor a hostname. Typically the result of stale agent "
        "registrations, network-only scans of unreachable hosts, or import "
        "errors. Stricter than the data-quality 'missing OS' rule, which "
        "flags on either gap alone."
    )
    DEFAULT_SEVERITY = "fail"
    SOURCES = (_SRC_ASSET_SEARCH,)
```

**Implementation strategy.** The `MissingOsRule` (`checks/data_quality.py`) already uses `POST /api/3/assets/search` with `operating-system is-empty` filter (server-side). We piggyback on that filter and **client-side narrow** to those that also have empty `hostName`:

```python
def run(self, client, t) -> RuleResult:
    if not t.flag_ghost_assets:
        return skipped_rule(...)

    # Server-side: assets with no OS fingerprint (small candidate set).
    body = client.post_one(
        "/api/3/assets/search",
        json_body={
            "filters": [{"field": "operating-system", "operator": "is-empty"}],
            "match": "all",
        },
        params={"size": _PER_ITEM_FINDING_CAP * 2},  # over-fetch a bit
    )
    candidates = body.get("resources", [])

    # Client-side: narrow to those also missing hostName.
    ghosts = [
        a for a in candidates
        if not (a.get("hostName") or "").strip()
    ]

    findings: list[Finding] = []
    emitted = 0
    for ghost in ghosts:
        if emitted >= _PER_ITEM_FINDING_CAP:
            break
        findings.append(Finding(
            severity="fail",
            message=f"Asset id={ghost.get('id')} has no OS and no hostname (ghost record)",
            details={
                "id": ghost.get("id"),
                "ip": ghost.get("ip"),
                "mac": ghost.get("mac"),
                "last_scan": ghost.get("history", [{}])[-1].get("date") if ghost.get("history") else None,
            },
        ))
        emitted += 1

    # Overflow rollup
    if len(ghosts) > emitted:
        findings.append(Finding(
            severity="warn",
            message=(
                f"{len(ghosts) - emitted} additional ghost assets omitted "
                f"from findings (capped at {_PER_ITEM_FINDING_CAP})"
            ),
        ))

    return make_rule_result(
        rule_id=self.RULE_ID,
        rule_name=self.RULE_NAME,
        description=self.DESCRIPTION,
        findings=findings,
        sources=list(self.SOURCES),
        summary={"ghost_count": len(ghosts), "candidates_examined": len(candidates)},
        default_severity=self.DEFAULT_SEVERITY,
    )
```

**Correctness caveat.** Over-fetching `size=2*cap` could miss ghosts beyond that bound if the OS-empty population is huge. Acceptable: on a real fleet OS-empty population is small (it's a problem indicator), and the rollup says "we capped." If a user reports this is undercounting, escalate to true pagination.

**Wiring:** Register in `AssetCoverageCheck._REGISTRY`-style call sequence at the end of the check's `run()`. Add to `tests/checks/test_asset_coverage.py` -- mock `client.post_one` to return predefined candidates.

**Config schema:** `AssetCoverageThresholds` needs a new bool field. Unknown-key rejection in `config.py` will require both the default value AND the validator update.

### F2 -- Report header Totals strip

**Files:**
- `src/rapid7_healthcheck/audit/snapshot.py` -- new `scans_total()` accessor
- `src/rapid7_healthcheck/report.py` -- new dataclass `InventoryTotals`; populate from snapshot; pass to template
- `src/rapid7_healthcheck/templates/report.html.j2` -- render the strip above the check list
- `src/rapid7_healthcheck/__main__.py` -- populate Totals from the same shared snapshot

**Snapshot accessor:**
```python
def scans_total(self) -> int:
    """Total scans across the deployment from /api/3/scans page metadata.

    Reads page.totalResources only -- does not enumerate the scan list.
    Mirrors total_asset_count(). Cached on first call.
    """
    if self._scans_total is None:
        body = self._client.get("/api/3/scans", params={"size": 1})
        self._scans_total = int(body.get("page", {}).get("totalResources", 0))
    return self._scans_total
```

Init field: `self._scans_total: int | None = None` in `__init__`.

**Dataclass in `report.py`:**
```python
@dataclass(frozen=True)
class InventoryTotals:
    total_assets: int
    total_sites: int
    total_scan_engines: int
    total_asset_groups_static: int
    total_asset_groups_dynamic: int
    total_scans: int
```

**Population logic** (in `__main__.py` after snapshot is built, before checks run):
```python
def _build_inventory_totals(snapshot: EnvSnapshot) -> InventoryTotals:
    groups = snapshot.asset_groups()
    static = sum(1 for g in groups if g.get("type") == "static")
    dynamic = sum(1 for g in groups if g.get("type") == "dynamic")
    return InventoryTotals(
        total_assets=snapshot.total_asset_count(),
        total_sites=len(snapshot.sites()),
        total_scan_engines=len(snapshot.scan_engines()),
        total_asset_groups_static=static,
        total_asset_groups_dynamic=dynamic,
        total_scans=snapshot.scans_total(),
    )
```

**Template change:** Add a small `<section class="inventory-totals">` block above the existing check list. Render as a horizontal strip of count tiles (label + value). Minimal CSS -- match the existing report style.

**Failure modes:** any of the snapshot accessors could fail. Wrap `_build_inventory_totals` in try/except and pass `None` to the template when it fails -- the template branches on `if inventory_totals` to skip rendering. This keeps a single accessor failure from killing the whole report.

**Important plumbing.** The `__main__.py` invocation passes `snapshot` to checks today. The Totals call must use the **same** snapshot instance to avoid duplicate API calls. Position the `_build_inventory_totals(snapshot)` call after `EnvSnapshot` construction but before the check loop.

**Delta blob impact:** the inventory totals are point-in-time and do not enter the delta projection. No `_state_blob_projection` changes.

**Verification:**
- Snapshot accessor unit tests (happy path, 404 → 0 / propagation? -- the accessor doesn't catch errors today; total_asset_count doesn't either, so this matches).
- `_build_inventory_totals` returns the expected `InventoryTotals` from a known snapshot.
- Template rendering test (an end-to-end report test exists somewhere -- find it).
- The render falls back gracefully when `inventory_totals` is `None` (one snapshot failure mode test).

## Task ordering (rationale)

1. **M1-M6 first** -- small, isolated, mechanical cleanups. Land them in close-grouped commits.
2. **C1 + F3** -- trivial value bump + 1-line feature. Quick wins.
3. **F1 (Ghost Assets)** -- new rule, larger scope. Lands on a stable base.
4. **F2 (Totals strip)** -- biggest. Saved for last because it touches the most files (snapshot + report + template + __main__).
5. **CHANGELOG + version** -- release prep.
6. **Final review** -- cross-branch.

Sequential, not parallel -- overlapping edits to `checks/scan_engines.py` (M2 + M3) and `audit/snapshot.py` (F2) make parallelism brittle for limited gain.

# 0.2.1 -- Polish + Tech-debt sweep -- Design

**Date:** 2026-04-30
**Target version:** 0.2.1
**Status:** Approved

## Goal

Clear out 0.2.0 review follow-ups and the long-deferred audit-config tech debt in one combined release. No new user-facing features; small UX correctness improvements + internal consolidation.

## Scope

Two parallel tracks with no inter-dependency:

- **Polish track** -- surgical fixes to 0.2.0 carryover items (error-chip dead code, cosmetic JS, regression test, spec-doc update)
- **Tech-debt track** -- audit-config validator dedup, rule-registration relocation, two missing tests, two minor cleanups

Out of scope:
- Widening `data-search-text` truncation (200-char cap stays; backlog says flag only if users report misses, none have)
- Phase 3 features (any larger UI work)
- Any change to the delta/state-blob format
- Any change to exit-code semantics

## Components

### Polish track

#### 1. Error-chip dead-code cleanup

**File:** `templates/report.html.j2`

The severity URL-hash whitelist at ~line 651 includes `'error'`, but no Error chip is rendered anywhere. The corresponding `body[data-filter-severity="error"] section.check > details:not(...)` CSS hide rule is therefore unreachable.

**Change:**
- Remove `'error'` from the JS whitelist array
- Delete the `body[data-filter-severity="error"]` CSS hide rule
- Do **not** render a new Error chip -- error status is an exception path (rule crashed), not a category users filter to

#### 2. Native-`<details>` spec-doc update

**File:** `docs/superpowers/specs/2026-04-30-0.2.0-phase2-design.md`

The original Phase 2 spec called for replacing native `<details>` with `<button aria-expanded aria-controls>` toggles. During 0.2.0 implementation we reverted to native `<details>` for accessibility (built-in keyboard handling, screen-reader semantics). CHANGELOG already notes this; spec doc does not.

**Change:**
- Add a short note in the rule-card section of the Phase 2 spec stating the final decision was native `<details>` and pointing at the CHANGELOG rationale

#### 3. Filter-isolation regression test

**File:** `tests/test_report_filtering.py` (new)

Commit `a91f6d1` fixed a critical bug where descendant-combinator CSS (`section.check details:not([data-severity="X"])`) hid inner finding-`<details>` along with rule cards. Fix changed to child combinator (`section.check > details:not(...)`).

This is structurally easy to regress. Pin it with a static-HTML test.

**Change:**
- New test renders a report and asserts: every CSS hide rule under `body[data-filter-severity="..."]` uses `section.check > details` (child combinator `>`), not bare descendant `section.check details`
- Test uses `re.findall` over the rendered HTML; no DOM parser dependency

#### 4. Cosmetic JS cleanups

**File:** `templates/report.html.j2`

Two harmless-but-unclean spots in the inline JS:

- `syncHash` empty-state uses literal `' '` (single space) as a sentinel. Replace with explicit `location.pathname + location.search` for readability.
- Theme-toggle `apply()` rewrites `localStorage.theme` on init even though the FOUC head script already set `data-theme` to the same value. Idempotent but noisy. Add a one-line guard: skip the localStorage write if the new value equals the existing stored value.

**Change:**
- `syncHash`: replace `' '` sentinel with `location.pathname + location.search`
- `apply()`: skip localStorage write when value is unchanged

### Tech-debt track

#### 5. Audit-config validator helper

**File:** `src/rapid7_healthcheck/config.py`

`_build_audit_config`, `_build_user_audit_config`, and `_build_report_config` all follow the same shape: check unknown keys → check required keys → per-field type-check → build dataclass. Three hand-rolled validators is one too many; the backlog has bumped this to **important**.

**Change:**
- Add private `_validate_dict_schema(data: dict, *, expected: set[str], required: set[str], types: dict[str, type | tuple[type, ...]], name: str) -> None`
  - Raises `ConfigError` on: unknown keys, missing required keys, type mismatches
  - `name` is the user-facing config-block name for error messages (e.g. `"audit"`)
- Rewrite each `_build_*` to call the helper, then construct its dataclass with defaults
- Default factories (`_default_user_audit`, `_default_audit`) **untouched** -- the duplication there is shallow and not load-bearing
- All existing `ConfigError` messages preserved verbatim where possible (tests assert on them)

#### 6. Rule-import relocation

**Files:** `src/rapid7_healthcheck/__main__.py`, `src/rapid7_healthcheck/audit/__init__.py`, `src/rapid7_healthcheck/audit/user_permission/__init__.py`

Currently `__main__.py` carries 19+ side-effect rule imports. Adding a rule means touching `__main__.py`, which violates the "wiring only" rule documented in CLAUDE.md.

**Change:**
- Move `from rapid7_healthcheck.audit.rules import <module>` lines from `__main__.py` into `audit/__init__.py` (currently empty)
- Move `from rapid7_healthcheck.audit.user_permission.rules import <module>` lines into `audit/user_permission/__init__.py`
- Use a `from . import rules_module_a, rules_module_b, ...` form so `noqa: F401` isn't needed at every line; one suppression at the import block is fine
- Update CLAUDE.md "Audit subsystem internals" paragraph: replace the "today they're imported by side effect when `__main__.py` loads" wording with "imported by side effect when the `audit` / `audit.user_permission` package loads"

#### 7. Users-endpoint-404 self-skip test

**File:** `tests/audit/test_user_permission_orchestrator.py` (extend) or new file if missing

`UserPermissionAuditCheck.run()` short-circuits to `status="skipped"` when the `/users` endpoint returns 404 (older on-prem consoles). Orchestrator dispatch is covered; this self-skip path is not.

**Change:**
- New test: build a fake client whose `get_paginated("/users", ...)` raises `Rapid7ClientError(status_code=404, ...)`; run the orchestrator; assert `result.status == "skipped"` and a clear `result.message` mentioning the missing endpoint
- Branch on `e.status_code == 404`, never on substring match (per CLAUDE.md)

#### 8. Role-id comment

**File:** `src/rapid7_healthcheck/audit/user_permission/rules/disabled_user_with_role_bindings.py`

`role["id"]` in this rule is the role-name string (e.g. `"global-admin"`, `"user"`), not a numeric identifier. Future readers will assume integer.

**Change:**
- Add one-line comment at the `role["id"]` access site noting the value is a role-name string

#### 9. Deferred-import normalization

**Files:** `src/rapid7_healthcheck/audit/__init__.py`, `src/rapid7_healthcheck/audit/user_permission/__init__.py`

`UserPermissionAuditCheck.run()` has a deferred `EnvSnapshot` import; the configuration-audit orchestrator may or may not. Backlog item 11 (with the broadened scope: verify both, normalize to whichever pattern wins).

**Change:**
- Verify each orchestrator's `EnvSnapshot` import is still required for circular-import reasons (try hoisting locally and run the test suite; if green, hoist permanently)
- Normalize both orchestrators to the same import location (top-level if possible, deferred only if mandatory)
- If both must stay deferred, leave them but ensure both have a one-line comment explaining the cycle

## Testing strategy

- Existing suite stays green (currently 294 passing)
- New tests:
  - `tests/test_report_filtering.py` -- child-combinator CSS pinned
  - Users-404 self-skip -- orchestrator returns `status="skipped"` cleanly
- No new fixtures needed; reuse existing report-render fixtures and the fake-client patterns already in `tests/audit/`
- Validator-helper refactor must preserve existing error messages exactly -- `tests/test_config.py` will assert this

## Risks

- **Validator refactor** -- the three `_build_*` functions are tested via `test_config.py`; refactor must not change error-message text or `ConfigError` semantics. Run the config tests early in the implementation.
- **Rule-import relocation** -- if a side-effect import is removed and not added to the package `__init__.py`, the rule silently disappears from runs. Mitigation: assert `len(_RULE_REGISTRY)` after import in a sanity test, and run a real audit-rule test to confirm registration fires.
- **Deferred-import hoisting** -- if a circular-import was the original reason and we miss it, hoisting will break startup. Mitigation: actually run `python -m rapid7_healthcheck --help` after the change.

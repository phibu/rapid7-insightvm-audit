# 0.2.2 — Polish, Correctness, Diagnostics — Design

**Date:** 2026-04-30
**Target version:** 0.2.2
**Status:** Approved

## Goal

Three correctness fixes (data-quality perf, asset-coverage operator, agent-rule timeout investigation), one diagnostic improvement (better rule-error visibility), two report-UX polish items, and two CLI-UX features that make long runs observable. No new audit rules — those are deferred to 0.2.3.

## Scope

In:
- Performance/correctness fixes for three operational/audit code paths surfaced by a real 0.2.1 run against a >100k-asset environment.
- Diagnostic-surface improvement so future rule errors are root-causable from the report.
- Default-on file log + console progress status line so long runs aren't silent.
- Two surgical report-polish fixes (filter-bar scroll-margin, hash-link auto-expand).
- One README/CLAUDE.md doc clarification on the sampling story.

Out (deferred to 0.2.3):
- New audit rules (engine version, engine OS, agent presence, agent version, complementary scanning).
- Mid-run re-authentication / session-refresh logic. The `privileged_user_without_mfa` `auth failed` issue gets *diagnostic surfacing* in 0.2.2; the *fix* needs evidence from a follow-up run.

## Components

### 1. Correctness fixes

#### 1.1 `DataQualityCheck.flag_missing_os` — performance

**File:** `src/rapid7_healthcheck/checks/data_quality.py`

The current path at `data_quality.py:31` materializes the entire `/api/3/assets/search` result set just to take `len()` and slice ten examples. With >100k matching assets, that's ~200 paginated POSTs. Observed runtime: 28 minutes.

**Change:** issue a single POST with `size=10`, read `page.totalResources` for the count, use the returned 10 resources as `examples`. Mirror the empty-sites pattern at `data_quality.py:44`.

```python
body = client.post("/api/3/assets/search", json_body=missing_filter, params={"size": 10})
total = int(body.get("page", {}).get("totalResources", 0))
examples = body.get("resources", [])[:_EXAMPLES_LIMIT]
```

(Implementation will use whatever single-request method `client.py` exposes; if only `paginate_post` is available, add a `post_one(...)` helper or call the underlying request directly.)

Same JSON output shape (`summary.missing_os_count`, finding `details.total`/`examples`). Single request instead of ~200. Expected runtime: seconds.

#### 1.2 `AssetCoverageCheck.flag_unscanned_assets` — invalid operator

**File:** `src/rapid7_healthcheck/checks/asset_coverage.py`, `src/rapid7_healthcheck/config.py`, `docs/examples/config.yaml`, `README.md`

The current path at `asset_coverage.py:42` uses `operator: "is-empty"` on `field: "last-scan-date"`. Per the canonical Rapid7 `/api/3/assets/search` filter spec (verified via Context7 against `riza/rapid7-insightvm-api-docs`), `is-empty` is **not a valid operator on `last-scan-date`** — that operator is only listed for string fields like `host-name` and `operating-system`. The valid date operators on `last-scan-date` are `is-on-or-before`, `is-on-or-after`, `is-between`, `is-earlier-than`, `is-within-the-last`. The 400-trap fallback (lines 48-56) has been masking the wrong-operator bug as "console-version difference" since 0.1.x.

**Change:** replace with `is-earlier-than` plus a new `asset_coverage.never_scanned_days` threshold (default `90`):

```python
unscanned_filter = {
    "filters": [
        {"field": "last-scan-date", "operator": "is-earlier-than", "value": t.never_scanned_days}
    ],
    "match": "all",
}
```

Drop the now-unreachable 400-trap (lines 48-56) and the `unscanned_unavailable` finding. Update:
- `AssetCoverageThresholds` dataclass in `config.py` (add `never_scanned_days: int`)
- `_build_thresholds` validator (extend `_THRESHOLD_NESTED` accordingly — `_from_dict` picks up the new field automatically once it's on the dataclass)
- `docs/examples/config.yaml` (add `never_scanned_days: 90` under `thresholds.asset_coverage`)
- README thresholds table

#### 1.3 `agent_unauth_collision` — read-timeout at fleet scale

**Files:** `src/rapid7_healthcheck/audit/rules/agent_unauth_collision.py`, possibly `src/rapid7_healthcheck/audit/snapshot.py`

The `agent_unauth_collision` rule errored with `network error after N attempt(s) on ...: Read timed out` on the same 0.2.1 run against >100k assets. Endpoint slowness ruled out by user — the rule itself is doing too much work at fleet scale.

**Approach:** investigate first. Implementation plan starts with reading the rule + its snapshot accessors, identifying whether it iterates per-asset / per-site without honoring `sample_size`, then deciding between:

- **(a) Route iteration through a sampled `EnvSnapshot` accessor** if the rule logic tolerates sampling (most agent-collision detection is "show me examples of bad config", not "count every instance").
- **(b) Add a count-only fast path** (mirroring 1.1) if the rule must touch every asset, e.g. via `/api/3/assets/search` with a server-side filter that captures the rule's predicate.

The plan will not pre-decide the fix; the implementation task starts with an investigation step that produces a one-paragraph finding and a chosen approach before any code is written.

### 2. Diagnostic surface (rule-error visibility)

**Files:** `src/rapid7_healthcheck/audit/__init__.py`, `src/rapid7_healthcheck/audit/user_permission/__init__.py`, `src/rapid7_healthcheck/report.py`, `src/rapid7_healthcheck/templates/report.html.j2`

Today when a rule raises, the orchestrator catches it and stores `str(e)` on `RuleResult.error`. Thanks to the v0.1.7 diagnostics format, the error string already contains the failing API path and method, but it's a single opaque blob in the report.

**Change:** add two optional fields to `RuleResult`:

```python
@dataclass
class RuleResult:
    # existing fields ...
    error_path: str | None = None         # API path of the failing request
    error_status_code: int | None = None  # HTTP status code if applicable
```

Both audit orchestrators' exception traps populate these when the caught exception is a `Rapid7ClientError`:

```python
except Exception as e:
    error_path = None
    error_status_code = None
    if isinstance(e, Rapid7ClientError):
        error_status_code = e.status_code
        m = re.search(r' on \w+ (/api/3/[^\s:]+)|(?: at )(/api/3/[^\s:]+)', str(e))
        if m:
            error_path = m.group(1) or m.group(2)
    rule_results.append(RuleResult(
        # existing fields ...
        error=str(e),
        error_path=error_path,
        error_status_code=error_status_code,
    ))
```

The report template renders these inline when present:

> **Error:** auth failed
> *Failed call:* `GET /api/3/users/42/authentication-tokens` (401)

This unblocks root-cause investigation of `privileged_user_without_mfa` (and any future similar rule failures) without committing to a retry/re-auth design now. On the next run the report itself tells us which endpoint/status caused the failure.

### 3. CLI UX

#### 3.1 Default-on run log

**Files:** `src/rapid7_healthcheck/__main__.py` (or new small `logging_setup.py`)

Today `--log-file <path>` exists but is opt-in; failed runs without the flag leave only stderr captured.

**Change:**
- New CLI flag `--no-log-file` (suppresses the auto-log).
- `_setup_logging` adds a `FileHandler` for a resolved log path:
  - If `--no-log-file`: no file handler.
  - Else if `--log-file <path>`: explicit override, use that path.
  - Else: derive from `cfg.report.output_dir` + filename pattern, replacing `.html` with `.log`. If `--output <path>` is given, mirror that with `.log` suffix.
- If the resolved file can't be opened (permission denied, missing dir), log a warning to stderr and continue without file output. Don't abort the run.
- Format unchanged: existing `%(asctime)s %(levelname)s %(name)s: %(message)s`. Plain text. Opens in built-in viewers on Windows + macOS.

Status-line updates from §3.2 do **not** route here — they're UX, not diagnostic data.

#### 3.2 Console progress status line

**File:** `src/rapid7_healthcheck/progress.py` (new)

Today `_run_checks` logs `running check: <name>` once per check at INFO. Long audit runs (with many rules iterating sites) sit silent for minutes between log lines. The 28-minute Data Quality run wasn't visibly progressing.

**Change:** new `ProgressReporter` class (writes directly to `sys.stderr`, bypassing the logger):

```python
class ProgressReporter:
    def __init__(self, stream=sys.stderr):
        self._stream = stream
        self._tty = hasattr(stream, "isatty") and stream.isatty()
        self._last_was_status = False

    def step(self, current: int, total: int, label: str) -> None:
        line = f"[{current}/{total}] {label}"
        if self._tty:
            self._stream.write("\r\x1b[K" + line)
        else:
            self._stream.write(line + "\n")
        self._stream.flush()
        self._last_was_status = self._tty

    def done(self, current: int, total: int, label: str, duration_ms: int) -> None:
        line = f"[{current}/{total}] {label} ({duration_ms}ms)"
        if self._tty:
            self._stream.write("\r\x1b[K" + line + "\n")
        else:
            self._stream.write(line + "\n")
        self._stream.flush()
        self._last_was_status = False

    def newline_if_needed(self) -> None:
        if self._last_was_status:
            self._stream.write("\n")
            self._last_was_status = False
```

Wired in:
- `_run_checks` (`__main__.py`) — outer counter over `_REGISTRY` (e.g. `[3/6] Configuration Audit`).
- Both audit orchestrators (`audit/__init__.py`, `audit/user_permission/__init__.py`) — inner counter over the rule registry (e.g. `[7/12 audit] agent_unauth_collision`). Each completed rule shows duration.

`newline_if_needed()` is called before any non-progress write that follows a status line (e.g. the final report-path `print(out.resolve())` in `__main__.run`).

### 4. Report polish

#### 4.1 Filter-bar overlap on hash-link scroll

**File:** `src/rapid7_healthcheck/templates/report.html.j2`

The sticky filter bar covers the top of a rule card after a hash-link scroll. Browser-native fix:

```css
section.check {
  scroll-margin-top: 90px;
}
```

Sized for the desktop bar height (~70px) plus a small visual gap. Slightly off when the bar wraps on narrow viewports; acceptable for v1, can revisit if reported.

#### 4.2 Summary-tile click auto-expands rule

**File:** `src/rapid7_healthcheck/templates/report.html.j2`

Today the editorial-band summary tiles are anchor links to `#rule-<id>`. The browser scrolls but leaves the native `<details>` collapsed.

**Change:** small inline JS, appended to the existing inline `<script>` block:

```javascript
(function(){
  function expandFromHash() {
    var hash = location.hash.replace(/^#/, '');
    if (!hash) return;
    var target = document.getElementById(hash);
    if (!target) return;
    var details = target.matches('details') ? target : target.querySelector(':scope > details');
    if (details) details.open = true;
  }
  window.addEventListener('hashchange', expandFromHash);
  expandFromHash();
})();
```

Uses `:scope > details` (child combinator, same discipline as the 0.2.0 filter fix) so only the outer rule card opens — inner finding-`<details>` are unaffected.

No-JS fallback: native `<details>` stays collapsed; link still scrolls to the right place (now under the filter bar thanks to §4.1). Acceptable.

## Risks

- **§1.1 perf fix vs first-page consistency** — using page 1's `totalResources` assumes the search response is consistent within a single request. Rapid7's API satisfies this by design (it's a synchronous count). Verify in the implementation by reading `client.py`'s response-handling for `/api/3/assets/search`.
- **§1.3 (agent_unauth_collision) is investigation-shaped** — the implementation plan must pause for a finding paragraph before coding. If the rule's logic genuinely needs every asset and the predicate isn't expressible as a server-side filter, the fix gets harder. Mitigation: if the investigation reveals a wider rewrite, split it out and either ship just §1.1 + §1.2 in 0.2.2 or scope §1.3 down to "add per-rule timeout knob so it fails predictably" as a stopgap.
- **§3.2 progress reporter on Windows cmd.exe** — `\x1b[K` (ANSI clear-line) requires Windows Terminal / PowerShell 7 / a VT-enabled console. On legacy `cmd.exe` it prints literal escape codes. Mitigation: `os.system("")` enables VT processing on Windows ≥10; call once at startup if the stream is a TTY on Windows. Or accept the legacy-cmd cosmetic glitch as a known limitation since the project's primary targets are PowerShell 7+ and macOS Terminal.
- **§4.2 hash-on-load timing** — the IIFE runs at end of body, so it executes after the rule cards exist in the DOM. No race. The browser's hash-scroll has already happened by then; setting `details.open = true` after scroll is fine — the browser doesn't re-scroll.

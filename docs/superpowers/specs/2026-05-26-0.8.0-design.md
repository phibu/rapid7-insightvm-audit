# 0.8.0 — Template Configuration Audit (new vertical)

**Date:** 2026-05-26
**Type:** Minor release (new audit vertical + 14 rules)
**Branch:** `release/0.8.0`

## Motivation

The audit tool today has three verticals — Configuration Audit, User & Permission Audit, Cloud Drift Audit. Configuration Audit contains three template-related rules but they're all **template ⇄ site relationship** rules (`policy_and_vuln_in_same_template`, `discovery_template_on_prod_site`, `site_vuln_template_no_creds`).

Nothing audits **a scan template's own settings**. A template can have vulnerability assessment enabled but no actual checks selected, run the policy engine against zero policies, leave potential-checks disabled (silently hiding ~30% of findings), have an invalid Telnet regex that never matches, etc. These misconfigurations produce scans that complete successfully but report degraded or wrong results.

This release adds a 4th audit vertical — **Template Configuration Audit** — with 14 rules covering template-internal correctness. The three existing template-related rules stay in Configuration Audit (they're a different shape).

## Architecture

### New vertical scaffold

```
src/rapid7_healthcheck/audit/
├── __init__.py                    # existing — Configuration Audit
├── snapshot.py                    # existing — gains templates_full()
├── rules/                         # existing — Configuration Audit rules
├── user_permission/               # existing
├── cloud_drift/                   # existing
└── template/                      # NEW
    ├── __init__.py                # orchestrator + TemplateAuditCheck + register_template_rule + side-effect imports
    └── rules/
        ├── __init__.py
        ├── vuln_enabled_but_no_checks.py
        ├── ... (one file per rule)
        └── ...
```

**Orchestrator** mirrors `audit/user_permission/__init__.py`:
- `_TEMPLATE_RULE_REGISTRY: dict[str, Rule]`
- `@register_template_rule` decorator
- `TemplateAuditCheck` class implementing `Check` Protocol
- Per-rule isolation via `safe_run`-style try/except
- Returns `CheckResult` with `rule_results: list[RuleResult]`

**Config integration:**
- New `TemplateAuditConfig` dataclass in `config.py` with `enabled: bool`, `full_scan: bool`, `sample_size: int`, `rules: dict[str, dict]`
- New `_VALID_TEMPLATE_AUDIT_RULE_IDS` set
- New entry in `checks:` toggle block: `template_audit: bool` (default True)
- Validator follows the existing `user_audit` pattern exactly

**`templates_full()` snapshot accessor:**

```python
def templates_full(self) -> list[dict]:
    """Return all scan templates from /api/3/scan_templates with full
    nested settings (checks, discovery, web, policy, database, telnet).

    Paginated per v3 spec. Cached on first call. Each item is the full
    ScanTemplate envelope per the v3 OpenAPI schema.

    Distinct from `scan_template(id)`, which fetches a single template
    by ID for callers that already know the ID — template_audit rules
    walk the full list and benefit from one paginated fetch.
    """
    if self._templates_full is None:
        self._templates_full = list(self._client.paginate("/api/3/scan_templates"))
    return self._templates_full
```

Init field: `self._templates_full: list[dict] | None = None` in `__init__`.

**Sampling**: templates are dozens-to-low-hundreds on real consoles. Most rules run full-population. Two exceptions:
- `near_duplicate_templates` is O(N²) — skip when `len(templates) > sample_size` and log info.
- `disabled_checks_in_individual_overrides` iterates one nested array per template; trivial.

### Severity philosophy

- **fail** — template produces demonstrably wrong results (vuln-enabled with no checks; policy-enabled with no policies)
- **warn** — template likely produces degraded results (potential checks off, correlate off, web spider with no creds, etc.)
- **info** — flagged for awareness, doesn't escalate check status (informational tiles, exploratory rules like `orphaned_template`, `unsafe_checks_disabled`)
- **minor** — opinion-driven (extreme parallelism, enhanced_logging in prod)

### CHANGELOG framing

Position the section as: "InsightVM scan templates have 50+ tunable settings. A template can complete a scan successfully while producing wrong or degraded results because of a single misconfigured field. The new Template Configuration Audit walks every template and flags settings that don't match best practices."

## Rules

### F2 — Vuln-check + policy correctness (7 rules)

#### `template.vuln_enabled_but_no_checks` — **fail**

Flags: `vulnerabilityEnabled: true` AND `checks.types.enabled` is empty AND `checks.categories.enabled` is empty.

Real-world bug pattern: an admin disabled all categories thinking they were toggling a switch off, but actually nulled the entire check list. Template runs "vuln scan" performing zero checks.

```python
def run(self, snapshot, severity, full_scan, sample_size, rule_config):
    findings = []
    for t in snapshot.templates_full():
        if not t.get("vulnerabilityEnabled"):
            continue
        checks = t.get("checks") or {}
        types_enabled = (checks.get("types") or {}).get("enabled") or []
        categories_enabled = (checks.get("categories") or {}).get("enabled") or []
        if not types_enabled and not categories_enabled:
            findings.append(Finding(
                severity=severity,
                message=(
                    f"Template '{t.get('name')}' has vulnerabilityEnabled=true "
                    f"but no check types AND no check categories selected. "
                    f"The scan will run but perform zero vulnerability checks."
                ),
                details={
                    "template_id": t.get("id"),
                    "template_name": t.get("name"),
                },
            ))
    return RuleResult(..., card_summary={"examined": N_vuln_enabled, "passed": N - flagged, "failed": flagged})
```

`card_summary.examined` is **only the vuln-enabled subset**, not all templates (a discovery-only template has nothing to evaluate here).

#### `template.potential_checks_disabled` — warn

Flags: `vulnerabilityEnabled: true` AND `checks.potential: false`.

Potential checks are how the platform reports findings it can't 100% confirm. Disabling them silently hides ~30% of findings on most consoles. Common admin mistake post-incident ("too noisy, turn off potential").

#### `template.correlate_disabled` — warn

Flags: `vulnerabilityEnabled: true` AND `checks.correlate: false`.

The OS-correlation step de-duplicates findings across check engines. Disabling it produces noisy reports with duplicate vulns.

#### `template.unsafe_checks_disabled` — info

Flags: `vulnerabilityEnabled: true` AND `checks.unsafe: false`.

Many orgs *intentionally* leave this off (unsafe = can crash the target). Info-only finding so users see the state but check doesn't escalate.

#### `template.disabled_checks_in_individual_overrides` — warn (minor)

Flags: `len(checks.individual.disabled) > threshold` (default 20).

`checks.individual.disabled: array` per spec. Per-check overrides are a common dumping ground that drifts over time. Knob: `max_disabled_individual_checks` (int, default 20).

#### `template.policy_enabled_but_no_policies_selected` — **fail**

Flags: `policyEnabled: true` AND `policy.enabled` is empty.

Template runs the policy engine against zero policies. Symmetric to `vuln_enabled_but_no_checks`. Per spec: `Policy.enabled: array` of policy identifiers.

#### `template.policy_only_template_attached_to_vuln_site` — info

Flags: `vulnerabilityEnabled: false AND policyEnabled: true` template bound to a site whose name OR `importance` suggests it's the org's primary vuln target.

Cross-references `snapshot.sites()`. Implementation: for each policy-only template, scan `snapshot.sites()` for ones with `scanTemplate.id == template.id` (or string match per the dual-shape helper `EnvSnapshot.site_scan_template_id`). If the site's `importance` is "high" or "very_high", flag as info.

### F3 — Discovery / web spider / database / telnet (6 rules)

#### `template.service_discovery_disabled` — warn

Flags: `discovery.asset.tcpPorts: []` AND `discovery.asset.udpPorts: []`.

Per spec: empty port lists mean "no service discovery." Scans against unknown port footprints. The cross-check: if `vulnerabilityEnabled: true` AND discovery has no ports, vulnerability checks can't target anything.

#### `template.web_spider_enabled_no_targets` — warn

Flags: `webEnabled: true` AND `web` object has empty/missing `includedPaths` AND no path-discovery enabled.

`web` is a freeform object in the schema; spec doesn't dictate its shape. Implementation: check `web.includedPaths` (or `web.startPaths`) is empty AND `web.discoveryEnabled` is False. Use defensive `.get(..., {}).get(..., [])` chains. If the shape doesn't match at all on a given console, emit an info finding noting the schema mismatch.

#### `template.web_spider_credentials_missing` — warn

Cross-rule: for each template with `webEnabled: true`, find sites using it, check if any site has HTTP-form or HTTP-headers credentials configured. Authenticated web scans return ~5× the findings of unauthenticated ones.

Implementation: `snapshot.site_credentials(site_id)` returns the credential list per site. Check the `account.service` field for `http-form-auth` or `http-headers-auth`. Per the spec drill, `SharedCredential.account` references `SharedCredentialAccount` — we'll defensively read whatever is in `account.service` since the schema is loose.

#### `template.database_targets_no_db_credentials` — warn

Flags: template has `database.oracle/postgres/db2` non-empty AND sites using it have no database credentials configured.

Cross-references `snapshot.site_credentials(id)` looking for `account.service` matching the database type. Same defensive shape handling.

#### `template.telnet_regex_unset` — info

Flags: all four telnet regex fields are empty (`loginRegex`, `passwordPromptRegex`, `failedLoginRegex`, `questionableLoginRegex`).

Cosmetic — telnet auth is rare today. Per spec these are all strings; check empty/None.

#### `template.telnet_regex_invalid` — warn

Flags: any of the four regex fields is a non-empty string that fails to compile via `re.compile()`.

Silent failure mode: the rule never matches because the regex is invalid. Catches the obvious typos.

### F4 — Hygiene + inventory (4 rules)

#### `template.template_inventory_summary` — info

One always-passes finding (or zero findings, status=pass) emitting an info-severity summary tile to anchor the section. Counts:
- Total templates
- Vuln-enabled count
- Policy-enabled count
- Discovery-only count
- Templates not used by any site (orphan candidates — see below)

This populates `summary` AND `card_summary` (`examined=total, passed=total, failed=0`) so the report's card-summary line renders informatively.

#### `template.parallel_assets_extreme` — minor (info)

Flags: `maxParallelAssets > 50` OR `maxParallelAssets < 2`.

Outliers signal performance fights. Knobs: `parallel_assets_min` (default 2), `parallel_assets_max` (default 50).

#### `template.enhanced_logging_in_prod` — info

Flags: `enhancedLogging: true` on a template bound to a site with `importance == "high"` or `"very_high"`. Blows up scan logs; useful for triage, not for steady state.

#### `template.near_duplicate_templates` — minor

Flags: two or more templates with ≥95% identical canonical-JSON settings (ignoring `id`, `links`, `name`).

Cap: skip rule entirely when `len(templates) > sample_size` (O(N²)). Log info: `"skipped because N templates exceeds sample_size threshold"`.

Implementation:
```python
def _template_signature(t: dict) -> str:
    """Canonical JSON of template settings, ignoring identity fields."""
    ignored_keys = {"id", "links", "name"}
    clean = {k: v for k, v in t.items() if k not in ignored_keys}
    return hashlib.sha256(
        json.dumps(clean, sort_keys=True, default=str).encode()
    ).hexdigest()

def _similarity(t1: dict, t2: dict) -> float:
    """Fraction of identical top-level fields (excluding identity)."""
    ignored = {"id", "links", "name"}
    keys = (set(t1) | set(t2)) - ignored
    if not keys:
        return 0.0
    matches = sum(1 for k in keys if t1.get(k) == t2.get(k))
    return matches / len(keys)
```

Threshold: 0.95 default. Knob: `similarity_threshold` (float, default 0.95).

#### Decision: `orphaned_template` — drop from this release

Rationale: sites can use a template via `/api/3/scans?template=X` ad-hoc override. The bulk listing endpoint doesn't surface this. False-positive risk is too high. Defer to a `someday` backlog entry pending real-world validation.

### Risk assessment

- **F1 scaffold** is the highest-architecture-risk piece. Mitigated by following the existing `user_permission` and `cloud_drift` patterns line-for-line — no new architectural ground broken.
- **F2-F4 rules** are low-risk individually. Each is a defensive read of a v3-spec-verified field with a defensive None-guard chain.
- **`near_duplicate_templates`** O(N²) is mitigated by the sample-size cap.
- **`web_spider_*` rules** have schema fuzziness (`web` is freeform). Mitigated by defensive `.get()` chains and a fallback info-finding if shape doesn't match.
- **Cross-rule (template ⇄ site) rules** add coupling between snapshot accessors. None should fail catastrophically — `safe_run` isolation absorbs per-rule errors as `status="error"` rule cards.

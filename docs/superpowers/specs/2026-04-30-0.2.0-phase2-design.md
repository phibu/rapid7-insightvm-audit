# 0.2.0 -- Report UI/UX Phase 2 Design Spec

**Date:** 2026-04-30
**Target release:** 0.2.0 (minor release -- interactivity layer)
**Status:** approved, ready for implementation plan
**Predecessors:** 0.1.9 (visual rewrite + delta strip), 0.1.10 (polish patch)
**Related design docs:** `docs/superpowers/specs/2026-04-29-report-ui-rework-design.md` (Phase 2 sections superseded by this doc)

## Summary

Add the interactivity layer to the self-contained HTML report. Sticky filter bar (severity chips, search box, conditional `Changed` chip) with URL-hash state, three-state theme toggle (light / dark / system) with `localStorage` persistence and FOUC prevention, `<noscript>` fallback, `prefers-reduced-motion` handling, and a static-HTML a11y test sweep.

Native `<details>` elements are retained for rule-card expansion (the original Phase 2 spec called for replacement; we kept the native element instead -- see Decision 1 below). Tech-debt items (validator dedup, `__main__.py` rule-imports, etc.) are deferred to 0.2.1.

~400-500 LOC across `templates/report.html.j2` plus a new `tests/test_report_a11y.py` file. No `report.py` changes; no data-model changes; no new HTTP, no new dependencies. Single PR.

## Goals

1. Filter findings by severity and search term without leaving the report.
2. Honor user theme preference: explicit override (light/dark) or follow OS (`prefers-color-scheme`).
3. Stay accessible -- keyboard, screen readers, JS-disabled, reduced-motion users all get a working report.
4. Preserve every Phase 1 invariant: single self-contained HTML file, no external resources, prints cleanly, opens offline.

## Non-Goals

- No JS rule-card toggle (native `<details>` stays -- see Decision 1).
- No localStorage filter persistence (URL-hash only -- see Decision 2).
- No browser-driven a11y testing (static HTML inspection only -- see Decision 3).
- No tech-debt sweep -- validator dedup, `__main__.py` rule-imports, role-id comment, deferred-import verification, endpoint-404 self-skip test all roll to 0.2.1.

## Hard Constraints (verified against the codebase)

- **Single self-contained HTML file.** No external CSS/JS/fonts/icons. All inline.
- **`tests/test_report.py::test_no_external_resources` continues to pass** with its 0.1.9 strengthened assertions.
- **No data-shape changes** to `CheckResult` / `RuleResult` / `Finding` / `ReportContext`.
- **No HTTP changes.** `client.py` is not touched.
- **No new dependencies.** No `BeautifulSoup`, no Playwright, no Tailwind. Plain `re` + DOM APIs.
- **All 287 existing tests stay green** at every commit. New tests added on top.
- **File size budget:** report stays under ~600 KB even in pathological environments. The `_state_blob_projection` 1 MB cap from 0.1.9 still applies and is unaffected.

## Key Decisions (with rationale)

### Decision 1: Native `<details>` retained -- no JS rule-card toggle

The original Phase 2 spec called for replacing native `<details>` with `<button aria-expanded aria-controls>`. We keep `<details>`.

**Rationale:** native `<details>` ships built-in keyboard support, screen-reader semantics, and zero-JS fallback -- three things we'd otherwise have to recreate. The "full row click target" advantage of replacement is nice-to-have, not load-bearing. Replacing would add ~30 lines of JS and complicate the `<noscript>` story.

### Decision 2: Filter state in URL hash only -- no localStorage

Filter chip state and search input serialize to `location.hash`; no `localStorage` for filters. Theme toggle DOES use `localStorage` (different concern -- user preference vs per-report state).

**Rationale:** filter state belongs to a specific report, not to the user. Persisting filters across reports risks hiding fails the operator hasn't seen yet. URL-hash works for the share-a-filtered-view case without that risk.

### Decision 3: A11y test is static HTML inspection -- no Playwright

Tests use `re` against rendered HTML. Cover load-bearing attributes (`aria-pressed`, `aria-label`, `role="toolbar"`, `:focus-visible` rule, `<noscript>` / `.no-js` plumbing, `prefers-reduced-motion` media query). No tab-order assertion (it's DOM order in static HTML by definition; we don't reorder via JS).

**Rationale:** real DOM testing requires Playwright (~80 MB dev dep, ~5s CI overhead). For a static HTML report with no runtime state mutation, static inspection catches every regression that matters. Tab order is verified by reading the DOM left-to-right, top-to-bottom -- the same way a browser computes it.

### Decision 4: Theme toggle is three-state -- `system → light → dark`

A two-state toggle would lose the "follow system" affordance once the user clicks once. Three-state preserves it. Default is `system` (no `localStorage` entry).

### Decision 5: Filter bar position -- sticky from where it first appears

`position: sticky; top: 0`. Pins from where it appears in document flow; doesn't overlap the editorial band on initial scroll. Standard pattern, less aggressive than fixed-top.

## Components

### Component 1: FOUC-prevention head script + `<noscript>` fallback

First thing after `<title>`, before any stylesheet. Inline, synchronous, runs before paint:

```html
<script>
(function(){
  document.documentElement.classList.remove('no-js');
  try {
    var t = localStorage.getItem('theme');
    if (t === 'light' || t === 'dark') {
      document.documentElement.setAttribute('data-theme', t);
    }
  } catch(e) {}
})();
</script>
```

`<html class="no-js">` set in markup. Script removes the class on JS-enabled browsers. CSS rule `.no-js .filter-bar, .no-js .theme-toggle { display: none; }` hides the interactive chrome when JS is off -- the rest of the report (verdict, delta, metrics, rules with native `<details>`) renders normally.

### Component 2: Filter Bar

Markup (inserted between metric grid and the first `<section class="check">`):

```html
<div class="filter-bar" role="toolbar" aria-label="Filter findings">
  <div class="filter-chips" role="group" aria-label="Filter by severity">
    <button class="chip" type="button" aria-pressed="true"  data-severity="all">All</button>
    <button class="chip" type="button" aria-pressed="false" data-severity="fail">Fail</button>
    <button class="chip" type="button" aria-pressed="false" data-severity="warn">Warn</button>
    <button class="chip" type="button" aria-pressed="false" data-severity="pass">Pass</button>
    <button class="chip" type="button" aria-pressed="false" data-severity="skipped">Skipped</button>
    {% if delta %}
    <button class="chip" type="button" aria-pressed="false" data-filter="changed">Changed</button>
    {% endif %}
  </div>
  <input class="filter-search" type="search" placeholder="Search rules…"
         aria-label="Search rules and findings">
</div>
```

CSS:
- `position: sticky; top: 0; z-index: 10;`
- Background fills with `--bg` and a 1px bottom border so it visually separates from scrolling content.
- Severity chips use semantic colors (existing `--{severity}-fg` / `--{severity}-bg` tokens) when active.
- `:focus-visible` ring matches existing 2px solid `--info-fg` outline.

**Filter semantics:**
- Severity chips are *exclusive*. "All" is default. Clicking one unsets the others. `aria-pressed` reflects state.
- `Changed` chip is *additive* with severity. Combines with whichever severity chip is active.
- Search box runs over `data-search-text` attributes. Debounce 150ms. Empty input clears the search.

**Filter mechanism (CSS-driven, JS only sets attributes):**

Each rule card carries:
- `data-severity="<status>"` -- set at render time from `rr.status`.
- `data-changed` (boolean attribute) -- set at render time when the rule has at least one finding signature in `delta.resolved | delta.new_fails | delta.severity_changed`.
- `data-search-text` -- at render time, lowercase concatenation of `rr.rule_name` + first 200 chars of each finding's message, joined with spaces.

JS toggles `<body>` attributes; CSS hides cards that don't match:

```css
body[data-filter-severity="fail"]    section.check details:not([data-severity="fail"])    { display: none; }
body[data-filter-severity="warn"]    section.check details:not([data-severity="warn"])    { display: none; }
body[data-filter-severity="pass"]    section.check details:not([data-severity="pass"])    { display: none; }
body[data-filter-severity="skipped"] section.check details:not([data-severity="skipped"]) { display: none; }
body[data-filter-changed]            section.check details:not([data-changed])            { display: none; }
body[data-filter-search]             section.check details:not([data-match])              { display: none; }
```

Search updates set/remove `data-match` on each card based on substring lookup against `data-search-text`. Single DOM walk per keystroke (debounced 150ms).

**URL hash sync** (`#severity=fail&changed&search=port%2022`):
- On page load, parse hash, apply chip + search-input state, set body attributes.
- On any state change, re-serialize and `history.replaceState({}, '', '#' + hash)` (no scroll jump, no history pollution).

### Component 3: Theme Toggle

Markup (right-aligned in the meta strip):

```html
<button class="theme-toggle" type="button" aria-label="Theme: system" data-theme-state="system">
  <span class="theme-icon" aria-hidden="true">
    <svg width="14" height="14" viewBox="0 0 16 16" ...>...</svg>
  </span>
  <span class="theme-label">System</span>
</button>
```

Three inline SVG icons, ~30 bytes each. Stored once in a hidden `<svg>` defs block; the button references via `<use href="#icon-system">` (or whichever current state). Switching state swaps the `<use href>` value and the visible label text.

**Behavior:**
- Cycle: `system → light → dark → system`.
- Each click: read `data-theme-state`, compute next, update `<html data-theme>` (or remove for `system`), update `localStorage.theme` (or remove for `system`), update button's `data-theme-state`/`aria-label`/visible label/icon.
- `localStorage` access wrapped in `try/catch` for private-mode robustness.

**CSS coordination:**

```css
@media (prefers-color-scheme: dark) { :root { ... dark vars ... } }
:root[data-theme="dark"]  { ... dark vars ... }
:root[data-theme="light"] { ... light vars ... }
```

`[data-theme]` rules are declared *after* the `@media` block so explicit override wins. Both paths must work: a system-dark user with `data-theme="light"` gets light; a system-light user with `data-theme="dark"` gets dark.

### Component 4: Reduced-motion handling

```css
@media (prefers-reduced-motion: reduce) {
  .chip, .theme-toggle { transition: none; }
}
```

Color flips and toggle button hover effects become instant. Native `<details>` open/close is already instant in most browsers; no rule needed there.

### Component 5: Print CSS additions

Extend the existing `@media print` block:

```css
@media print {
  /* ...existing rules... */
  .filter-bar { display: none; }
  .theme-toggle { display: none; }
}
```

The 0.1.10 force-expand-`<details>` rules already cover the rule-card content. Light theme is already forced in print via the `:root` var override.

### Component 6: A11y Test Sweep

New file `tests/test_report_a11y.py`. Seven tests, all using `re` over the rendered HTML string:

```python
def test_chips_have_aria_pressed():
    """Every filter chip must have aria-pressed for screen-reader state announcement."""
    html = render_report(_ctx_with_findings())
    chips = re.findall(r'<button[^>]*class="chip"[^>]*>', html)
    assert len(chips) >= 5  # All + 4 severities
    for chip in chips:
        assert 'aria-pressed=' in chip


def test_theme_toggle_has_aria_label():
    """Icon-only theme button needs aria-label for screen readers."""
    html = render_report(_ctx_with_findings())
    m = re.search(r'<button[^>]*class="theme-toggle"[^>]*>', html)
    assert m is not None
    assert 'aria-label="Theme:' in m.group(0)


def test_search_input_has_aria_label():
    """Search input needs an accessible name."""
    html = render_report(_ctx_with_findings())
    m = re.search(r'<input[^>]*class="filter-search"[^>]*>', html)
    assert m is not None
    assert 'aria-label=' in m.group(0)


def test_focus_visible_rule_present():
    """Focus indicator CSS rule must exist with an outline declaration."""
    html = render_report(_ctx_with_findings())
    assert ':focus-visible' in html
    assert re.search(r':focus-visible\s*\{[^}]*outline:', html) is not None


def test_filter_bar_has_role_toolbar():
    """Filter bar wraps controls with role=toolbar for ARIA semantics."""
    html = render_report(_ctx_with_findings())
    assert 'role="toolbar"' in html


def test_noscript_fallback_hides_interactive_chrome():
    """With JS off, .filter-bar and .theme-toggle must be hidden via .no-js."""
    html = render_report(_ctx_with_findings())
    assert 'class="no-js"' in html  # html element starts with no-js
    assert re.search(r'\.no-js\s+\.filter-bar', html) is not None
    assert re.search(r'\.no-js\s+\.theme-toggle', html) is not None


def test_reduced_motion_media_query_present():
    """Users with prefers-reduced-motion get a no-transition path."""
    html = render_report(_ctx_with_findings())
    assert '@media (prefers-reduced-motion: reduce)' in html
```

Test fixture `_ctx_with_findings()` returns a `ReportContext` with at least 2 audit rules and 2 findings so the filter bar renders with all chips.

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Sticky filter bar overlaps important content on small viewports | `top: 0` is the conservative default. Acceptable for first cut; can refine if reported. |
| URL-hash filter applied on load causes a flash of unfiltered content before JS runs | Filter JS runs at end of body -- flash is brief (one frame on most browsers). Could pre-set body attributes from a `<head>` script too -- overkill for v1. Add to backlog if reported. |
| `localStorage` unavailable (private mode, certain corp policies) | Wrapped in `try/catch`; falls back to per-page state. User can still cycle the toggle; choice doesn't persist. |
| `data-search-text` doubles DOM bytes for searchable content | Trimmed to first 200 chars per finding (Decision in section 2). Real-world ~12 KB per 50-rule report; acceptable. |
| Browser without `prefers-color-scheme` / `prefers-reduced-motion` | Falls through to defaults. Already true in 0.1.9. |

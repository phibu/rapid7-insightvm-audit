## Scope

### Correctness fixes (4)

#### C1 -- `local_account_when_sso_configured`: defensive external-source filter

**File:** `src/rapid7_healthcheck/audit/user_permission/rules/local_account_when_sso_configured.py`

The rule filters authentication sources with `s.get("external")`. The
`/api/3/authentication_sources` endpoint is absent from
`docs/research/api-v3.json`, so the field name `external` is unverifiable
against the spec. If the real field is `type` / `isExternal` / etc., the
filter silently returns `[]`, the rule always self-skips, and a real
misconfiguration (local accounts alongside SSO) is reported as a false pass.

**Fix:** Make the filter treat a source as external if **either**:
- `s.get("external")` is truthy, **or**
- `s.get("type")` is a non-empty string other than `"normal"`.

This mirrors the external-auth detection already used in
`privileged_user_without_mfa.py` (`_is_external_auth` -- anything other than
`authentication.type == "normal"` is external). Add a code comment recording
that the field name could not be verified against the committed spec and why
the dual check is defensive.

**User-visible:** Yes -- may surface local-account findings on consoles where
the rule previously self-skipped due to a field-name mismatch.

#### C2 -- `multiple_global_administrators`: zero-GA lower bound

**File:** `src/rapid7_healthcheck/audit/user_permission/rules/multiple_global_administrators.py`

The rule only fires on `len(gas) > max_ga`. Zero or one enabled Global
Administrator returns `pass` silently. Zero enabled GAs is a worse
misconfiguration than too many -- it means no one can administer the console.

**Fix:** Add a lower-bound check. When the count of enabled Global
Administrators is zero, emit a `fail`-severity finding ("No enabled Global
Administrator accounts found"). One or more GAs at or below `max_ga` stay
`pass`; above `max_ga` keeps the existing too-many finding. The zero-GA
finding is hard-coded `fail` regardless of configured severity -- a console
with no administrator is unambiguously broken (same pattern as the
never-seen hard-fail in `cd.scan_engine_cloud_registration`).

**User-visible:** Yes -- new `fail` finding on zero-GA consoles.

#### C3 -- `_ERROR_PATH_RE`: verb-optional path extraction

**File:** `src/rapid7_healthcheck/audit/__init__.py`

`_ERROR_PATH_RE`'s "from" branch requires `(?: from \w+ )` -- an HTTP verb
between "from" and the path. `cloud_client.py` raises
`f"non-JSON response from {path}: ..."` with no verb, so
`_extract_diagnostics` cannot extract the path from that error shape, and
the report's `error_path` is `None` for those errors.

**Fix:** Add a verb-optional branch to the regex that matches
`(?: from )((?:/api/3|/v4/integration)/[^\s:]+)` -- i.e. "from" directly
followed by a known API path prefix. Keep the existing verbed branch so
both shapes resolve.

**User-visible:** No -- diagnostics-only; affects `error_path` population.

#### C4 -- `scan_engine_cloud_registration`: normalize address/host_name keys

**File:** `src/rapid7_healthcheck/audit/cloud_drift/rules/scan_engine_cloud_registration.py`

The fallback cross-key index (`console.address ↔ cloud.host_name`) is
exact-match. Trailing whitespace or an FQDN trailing dot
(`engine.corp.example.com.`) silently misses, so a renamed engine that
should match via the fallback is wrongly reported as "missing from cloud."

**Fix:** Add a small `_normalize_host_key(value)` helper that lower-cases,
strips surrounding whitespace, and strips a single trailing dot. Apply it
both when building `cloud_by_host_name` and when looking up
`cloud_by_host_name.get(...)` so both sides are normalized consistently.
Empty/None values continue to be skipped as today.

**User-visible:** Yes -- the fallback match catches engines it previously
missed (fewer false "missing from cloud" findings).

### Cleanups (6)

#### L1 -- `single_engine_overload`: document the multi-site guard

**File:** `src/rapid7_healthcheck/audit/rules/single_engine_overload.py`

The `len(site_ids) < 2` guard skips engines bound to a single site, so a
one-site engine with a huge asset load is never flagged. The guard stays
(deliberate scope), but the rule `description` does not mention it.

**Fix:** Update the rule `description` to state the rule flags scan engines
shared across **two or more sites**. No code/behavior change.

#### L2 -- `site_vuln_template_no_creds`: drop the dead branch

**File:** `src/rapid7_healthcheck/audit/rules/site_vuln_template_no_creds.py`

`_shared_credential_covers` returns `True` for `siteAssignment ==
"all-sites"` early; the fallback then branches on `siteAssignment in (None,
"all-sites")` -- the `"all-sites"` arm is unreachable.

**Fix:** Remove the dead `"all-sites"` arm from the fallback so it only
handles the `None` case. No behavior change.

#### L4 -- Consolidate cloud-drift coercion helpers

**Files:** new `src/rapid7_healthcheck/audit/cloud_drift/_utils.py`;
`scan_engine_cloud_registration.py`; `stale_assessment_cohort.py`

`stale_assessment_cohort.py` imports the private `_coerce_positive_int` from
`scan_engine_cloud_registration.py` -- a cross-rule dependency on a private
symbol that breaks silently if the source rule is renamed.

**Fix:** Create `audit/cloud_drift/_utils.py` and move all three coercion
helpers into it: `_coerce_positive_int`, `_coerce_positive_float`,
`_coerce_optional_positive_int`. Both rule files import from `_utils`. The
helper behavior is unchanged -- pure relocation. Update the helper tests'
import paths.

#### L5 -- `overlapping_scan_windows`: `assumed_scan_duration_minutes` knob

**Files:** `src/rapid7_healthcheck/audit/rules/overlapping_scan_windows.py`;
`src/rapid7_healthcheck/config.py`; `docs/examples/config.yaml`

The rule substitutes a hardcoded `timedelta(hours=1)` when a schedule has
no/zero `duration`. The peer rule `scan_report_schedule_overlap.py` exposes
a configurable `assumed_scan_duration_minutes` (default 60) for the same
case.

**Fix:** Add an `assumed_scan_duration_minutes` option to the
`overlapping_scan_windows` rule config (default 60). Read it via the rule's
`rule_config`; substitute `timedelta(minutes=assumed_scan_duration_minutes)`
for the missing-duration case. Extend the `config.py` validator for the
rule's config block and add the default to `docs/examples/config.yaml`.
Default behavior is unchanged (60 min == the old hardcoded 1 hour).

#### L7 -- Remove `client.py:paginate_post`

**Files:** `src/rapid7_healthcheck/client.py`; its tests

`paginate_post` has had zero callers since the stale-assets perf fix
switched to `_bounded_asset_search`. It is dead code on the read-only
client.

**Fix:** Delete the `paginate_post` method and the tests that exercise it.
The CHANGELOG notes the public-API-surface removal. Verify no remaining
references via grep before committing.

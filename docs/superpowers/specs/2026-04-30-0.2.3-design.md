## Components

### 1. Bug fixes

#### 1.1 `agent_unauth_collision`: drop bogus `/history` endpoint

**Files:** `src/rapid7_healthcheck/audit/rules/agent_unauth_collision.py`, `src/rapid7_healthcheck/audit/snapshot.py`, `tests/audit/rules/test_agent_unauth_collision.py`

The rule's per-asset fallback constructs `GET /api/3/assets/{id}/history`. **This endpoint does not exist** per the canonical Rapid7 v3 API spec (verified via Context7). The valid asset sub-endpoints are `/services`, `/software`, `/databases`, `/files`, `/users` -- but **not `/history`**. The `history[]` array is a field on the asset record itself, returned inline by `GET /api/3/assets/{id}` and the paginated assets listing.

Why it took this long to surface: the bulk-listing assets endpoint may include `history[]` on some console versions but not others. The 0.2.2 cheap-signal fallback (introduced in Task 5 of 0.2.2) only fires when the `agent` block is absent -- but on consoles that omit BOTH `agent` AND inline `history`, the rule fell into the bogus per-asset call and 404'd.

**Change:**
- Replace `snapshot.asset_history(asset["id"])` with `asset.get("history", [])` inline read.
- If neither `agent` nor `history` is present on a given asset, treat as "no agent signal" (skip the asset -- don't call a non-existent endpoint).
- Delete `EnvSnapshot.asset_history` method entirely; no other callers exist.
- Update tests to use inline `asset["history"]` fixtures and assert `asset_history` is no longer called.

#### 1.2 `privileged_user_without_mfa`: 401 disambiguation

**Files:** `src/rapid7_healthcheck/audit/user_permission/rules/privileged_user_without_mfa.py`, `tests/audit/user_permission/rules/test_privileged_user_without_mfa.py`, `README.md`

Today the rule raises (errors out) on `Rapid7ClientError(status_code=401)` from `GET /api/3/users/{id}/2FA`. Two possible causes for that 401, with very different meanings:

1. **The calling user lacks Global Administrator** -- every user's `/2FA` returns 401. Treating this as "no MFA" produces false positives across the entire fleet.
2. **The user has no MFA configured** -- Rapid7's "no resource" pattern surfaces as 401 here. This is a genuine finding.

**Change:**
- Catch `Rapid7ClientError(status_code=401)` per-user inside the rule's loop instead of letting it propagate.
- **Disambiguation logic:**
  - Track per-user outcomes during the iteration.
  - If at least one user returned 200 (or 404), then 401s on other users are interpreted as "no MFA configured" → emit a finding at the configured severity.
  - If 100% of users 401, OR if the FIRST user 401s and no later user has yet returned 200, self-skip the entire rule with a single info finding: "Rule requires Global Administrator on the calling key. All users returned 401 from `/api/3/users/{id}/2FA`, which is the same response shape as no-MFA-configured -- disambiguation requires at least one successful response."
- Document the GA requirement in the rule's `description`.
- Update README user-audit table: parenthetical "(Requires Global Admin)" on this rule.

#### 1.3 Log-file parent-directory auto-create

**Files:** `src/rapid7_healthcheck/__main__.py`, `tests/test_logging_setup.py`

`_setup_logging` opens `logging.FileHandler(log_file, ...)` without ensuring the parent directory exists. If `cfg.report.output_dir` doesn't exist on disk, the run shows a confusing `Error: No such file or directory: <path>.log` warning. The graceful-degrade path catches the OSError and the run still succeeds, but the message looks fatal.

**Change:**
- Before instantiating the FileHandler, call `Path(log_file).parent.mkdir(parents=True, exist_ok=True)`.
- Mirrors what `write_report` does for the HTML output dir.
- Only fall to the existing OSError trap if mkdir itself fails (permission denied, disk full).
- Reword the warning message: drop the leading "Error:" feel; clarify it's a *log warning*, not a fatal error. The existing message format is `f"could not open log file {log_file!r}: {e}"`; consider `f"log file unavailable ({log_file}); continuing without file logging: {e}"`.
- Test: temp-dir fixture pointing at a non-existent subdir, assert the .log file gets created and no warning is logged.

### 2. New audit rules

#### 2.1 Shared `EnvSnapshot.agents()` accessor

**File:** `src/rapid7_healthcheck/audit/snapshot.py`

New lazy accessor mirroring the existing `users()`, `sites()`, `assets` patterns:

```python
def agents(self) -> tuple[list[dict], int]:
    """Return (sample_list, total_count) for the Insight Agent fleet.

    Lazily fetched and cached on first call. Honors `sample_size` when
    `full_scan` is False -- total_count comes from `page.totalResources`,
    sample_list is capped at sample_size.

    Returns ([], 0) cleanly when /api/3/agents is unavailable (404 on older
    consoles or non-GA keys). Both new agent rules consume this accessor;
    self-skip cleanly via the (_, 0) sentinel.
    """
```

Implementation:
- First page request: read `page.totalResources` for the count.
- If `full_scan == True`: paginate fully, materialize to list (still capped to a reasonable upper bound -- same upper bound as existing accessors).
- If `full_scan == False`: paginate until `len(sample) == sample_size`, stop.
- 404 handling: branch on `e.status_code == 404` (per CLAUDE.md), return `([], 0)` and set an internal `_agents_unavailable` flag. Other 4xx/5xx propagate.
- Cache the result tuple on `self._agents_cache` so multiple rules share one fetch.

#### 2.2 Rule: Insight Agent fleet presence

**File:** `src/rapid7_healthcheck/audit/rules/insight_agent_deployed.py`

```python
@register
class InsightAgentDeployedRule:
    rule_id = "insight_agent_deployed"
    rule_name = "Insight Agent Fleet Presence"
    description = (
        "Reports whether any Insight Agents are deployed in the environment. "
        "If zero agents are detected, agent-aware rules in this audit can't "
        "run and credentialed assessment relies entirely on network-credential "
        "scans. Severity is configurable; default `info` because some "
        "environments are intentionally agentless."
    )
    default_severity = "info"
    expensive = False
    sources = [
        "https://docs.rapid7.com/insightvm/insight-agent-overview/",
    ]
```

Behavior:
- Calls `snapshot.agents()`.
- If accessor returned `([], 0)` AND the snapshot's internal "unavailable" flag is set → self-skip with info finding ("`/api/3/agents` unavailable on this console").
- If `total_count == 0` → emit one finding at the configured severity: "No Insight Agents deployed in this environment."
- If `total_count > 0` → status `pass`, summary `{"agents_total": N}`.

Config block:
```yaml
audit:
  rules:
    insight_agent_deployed:
      enabled: true
      severity: info
```

`"insight_agent_deployed"` added to `_VALID_RULE_IDS` in `config.py`. Default block added to `docs/examples/config.yaml`.

#### 2.3 Rule: Insight Agent version currency

**Files:** `src/rapid7_healthcheck/audit/rules/insight_agent_version_currency.py`, `src/rapid7_healthcheck/audit/rules/_agent_version.py`

```python
@register
class InsightAgentVersionCurrencyRule:
    rule_id = "insight_agent_version_currency"
    rule_name = "Insight Agent Version Currency"
    description = (
        "Flags Insight Agents running versions more than `version_drift_minor` "
        "(default 1) minor versions behind the newest version observed in the "
        "fleet. Self-bootstrapping -- no hardcoded `latest` knob to maintain. "
        "Does NOT detect uniform fleet staleness (different rule territory)."
    )
    default_severity = "warn"
    expensive = False
    sources = [
        "https://docs.rapid7.com/insightvm/insight-agent-overview/",
    ]
```

The rule's logic:

1. `(agents, total) = snapshot.agents()`. If `total == 0` or unavailable → self-skip cleanly.
2. For each agent: scan `agent.get("software", [])` for an entry where `vendor == "Rapid7"` and `product` contains `"Insight Agent"` (case-insensitive). Extract `version` field (e.g. `"4.0.12.14"`).
3. Parse versions as `(major, minor, patch, build)` tuples via the new `_agent_version.parse_version(s)` helper. Agents with no Rapid7-Insight-Agent software entry, or with an unparseable version, are tallied in `agents_unparseable` and skipped from comparison.
4. `newest = max(parsed_versions)`. If fewer than 2 parseable agents (i.e. nothing to compare against), self-skip with info finding.
5. For each parseable agent: compute drift `= (newest.major - agent.major) * 1000 + (newest.minor - agent.minor)`. Flag if drift > `version_drift_minor` (default 1).
6. Findings include the agent's hostname, observed version, and the newest-in-fleet version for context.

Config block:
```yaml
audit:
  rules:
    insight_agent_version_currency:
      enabled: true
      severity: warn
      version_drift_minor: 1
```

The version parser (`_agent_version.py`) is a small focused module:

```python
def parse_version(s: str) -> tuple[int, int, int, int] | None:
    """Parse '4.0.12.14' or '4.0.12' or '4.0' into (major, minor, patch, build).

    Returns None if the string doesn't match the expected pattern. Missing
    components default to 0 (so '4.0' → (4, 0, 0, 0)).
    """


def find_agent_version(agent: dict) -> tuple[int, int, int, int] | None:
    """Extract the Rapid7 Insight Agent version from an agent.software[] block.

    Returns None if no Rapid7 Insight Agent software entry exists or its
```

## Risks

- **§1.1 -- `history[]` field not always populated.** If the bulk asset listing returns assets without `history[]` on some console versions, the rule will see no agent signal at all from those assets. Mitigation: that's the same outcome as today (the rule already skips when no signal). The fix changes the failure mode from "404 crash" to "silent skip," which is strictly better.
- **§1.2 -- disambiguation false-skip.** If only one user is checked AND they 401, the rule self-skips even if they genuinely have no MFA. Mitigation: in practice the rule iterates the full user fleet, so this only bites tiny environments. If it bites, the operator can run the audit via UI; documented in the rule description.
- **§2.3 -- version-string parser edge cases.** Rapid7 may format the agent version differently across console versions. Mitigation: parser returns None on any non-matching string; rule tallies these in `agents_unparseable` summary key so users can see how many agents fell through, and tests cover the common shapes.
- **§2.1 -- `agents()` 404 behavior.** Older consoles 404 on `/api/3/agents` per the user-permission orchestrator's existing self-skip pattern. Mirror that pattern to keep behavior consistent.

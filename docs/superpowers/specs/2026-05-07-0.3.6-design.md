# 0.3.6 — Agents Timeout, Progress UX, Pagination Log Demotion

Date: 2026-05-07
Target version: 0.3.6
Status: Approved (design phase)

## Summary

A bundle of three independent improvements that together polish the default-run UX and remove a known operational sharp edge:

1. **Tunable per-call timeout for `/api/3/agents`** — the 0.3.5 incident (`read operation timed out` raised by `insight_agent_deployed` against a slow on-prem console) has a config-only fix. New field `audit.agents_timeout_seconds`, default `180`. Snapshot passes this timeout to all four `/api/3/agents` call sites; the existing "skip on timeout" safety net stays in place.
2. **Per-check / per-rule progress lines** — new `ProgressReporter` writes structured progress to stderr, separate from the existing `logging` pipeline. TTY auto-detect by default, with `--progress` / `--no-progress` overrides.
3. **Demote `Paginating …` log line from INFO to DEBUG** — surgical: there is exactly one `logger.info(...)` call in `client.py` today (line 227, the pagination announcement). It moves to `logger.debug(...)`. Retries / backoffs / rate-limit waits are unaffected (none of them are INFO today).

The three concerns ship as three atomic commits in one release tag.

## Motivation

The 0.3.5 final review surfaced three closely related backlog items, all rooted in the same complaint: the default-run terminal output during long audits is simultaneously noisy (pagination chatter dominates) and uninformative (no signal of which rule is currently in flight). Operators on slow on-prem consoles also get hit by a hardcoded 60s timeout on `/api/3/agents` that today silently disables every agent-aware audit rule, with no operator-facing knob to fix it.

These three items pair naturally because they all change the per-run UX without changing audit semantics: same rules, same findings, same exit codes. Bundling them avoids three separate release-train cycles for one cohesive UX improvement.

## Non-goals

Explicit out-of-scope for 0.3.6:

- **Generalized per-path timeout map.** Only `audit.agents_timeout_seconds` is added; only `/api/3/agents` reads it. If a second slow endpoint shows up later, we generalize then.
- **`progress: auto|on|off` config field.** CLI flags + TTY auto-detect only. Forward-compatible — a config field can be added later without breaking the precedence rule.
- **Aggressive demotion of all `client.py` INFO logs.** Verified: there is exactly one `logger.info(...)` call in `client.py` today. Retries, backoffs, and rate-limit waits are not INFO.
- **Snapshot agent-head-request unification** (`agent_count()` / `agents()` / `agent_asset_ids_sampled()` each issue independent `GET /api/3/agents?size=1`). Documented in the `someday` backlog; remains there.
- **Removal of `insight_agent_version_currency` rule.** Pinned at 0.4.0; out of scope here.
- **README full refresh.** Only two README touches: one row in the threshold table for `audit.agents_timeout_seconds`, and a short mention of `--progress` / `--no-progress` in the CLI flags section.
- **`Check` Protocol signature changes.** Operational checks do not gain a `progress` parameter. Only the two audit orchestrators take a `progress: ProgressReporter | None = None` constructor arg.
- **`requests.Session` changes for timeout work.** Per-call `timeout=` kwarg only. Session-level defaults are unchanged.

## Architecture

Three independent vertical slices. No new architectural layers.

### Slice 1 — Agents timeout

- `client.py`: thread an optional `timeout: int | None = None` kwarg through `get(path, params, *, timeout=None)` → `_request(..., timeout=None)` → `requests.request(..., timeout=timeout if timeout is not None else self._timeout)`. Default behavior unchanged when caller passes nothing.
- `client.py`: same kwarg added to `paginate(path, params, *, timeout=None)` → `_paginate(..., timeout=None)`. The per-page worker reuses the same per-call timeout. The shared `requests.Session` is unchanged; per-call `timeout=` only.
- `config.py`: new field `audit.agents_timeout_seconds: int` on the audit dataclass; default `180`; validator rejects 0, negative, and non-int with `ConfigError` (exit `3`); unknown-keys-rejection convention preserved.
- `audit/snapshot.py`: read `self._agents_timeout = audit_config.agents_timeout_seconds` in `EnvSnapshot.__init__`; pass `timeout=self._agents_timeout` to all four `/api/3/agents` call sites (today at lines 453, 486, 531, 574 — head request in `agent_count()`, full pagination in `agent_asset_ids()`, full pagination in `agents()` when `full_scan`, sampled pagination in `agent_asset_ids_sampled()`).
- `docs/examples/config.yaml`: add the field with an inline comment pointing at the README.
- `README.md`: one new row in the threshold table.

### Slice 2 — Progress channel

- New file `src/rapid7_healthcheck/progress.py`. Single class:
  ```
  class ProgressReporter:
      def __init__(self, stream, enabled: bool): ...
      def check_start(self, idx: int, total: int, name: str): ...
      def check_done(self, name: str, elapsed: float): ...
      def rule_start(self, name: str): ...      # indented two spaces
      def rule_done(self, name: str, elapsed: float): ...
      def rule_skipped(self, name: str, reason: str): ...
  ```
  When `enabled=False`, every method is a no-op. Each `stream.write()` is wrapped in `try: ... except OSError: self._enabled = False` so a broken pipe latches the reporter off without aborting the run.
- `__main__.py`: construct one `ProgressReporter` at the top of `run()`. Precedence (per Q8):
  1. `--no-progress` → `False`
  2. `--progress` → `True`
  3. neither → `sys.stderr.isatty()`
- `__main__.py`: the orchestration loop owns `check_start` / `check_done` for every check (operational and audit alike) — these wrap the `check.run(...)` call from outside, so no `Check` protocol change is needed. Audit orchestrators additionally receive the reporter via constructor arg so they can emit per-rule events from inside their own `run(...)`.
- `audit/__init__.py` (`ConfigurationAuditCheck`) and `audit/user_permission/__init__.py` (`UserPermissionAuditCheck`): accept `progress: ProgressReporter | None = None`. Around each rule's `evaluate(...)` call, emit `rule_start` / `rule_done` (or `rule_skipped` when a rule is disabled). Use `try: rule_start; ... finally: rule_done` so a rule exception still closes the in-flight progress line.
- CLI: argparse `mutually_exclusive_group` for `--progress` / `--no-progress`. Both passed → argparse errors at startup (exit `3`).

### Slice 3 — Log demotion

- `client.py` line 227: `logger.info(...)` → `logger.debug(...)`. One line. No other changes.

## Data flow

### Slice 1

```
config.yaml (audit.agents_timeout_seconds: 180)
   │
   ▼
config.py loads → AuditConfig.agents_timeout_seconds: int
   │
   ▼
__main__.py builds EnvSnapshot(client, audit_config)
   │
   ▼
EnvSnapshot stores self._agents_timeout = audit_config.agents_timeout_seconds
   │
   ▼
agent_count() / agents() / agent_asset_ids() / agent_asset_ids_sampled()
   call client.get("/api/3/agents", ..., timeout=self._agents_timeout)
   or  client.paginate("/api/3/agents", timeout=self._agents_timeout)
   │
   ▼
client._request(...) uses the per-call value if not None,
   else falls back to self._timeout (60s default — unchanged for everyone else)
```

The snapshot's existing timeout-handling logic in `agent_count()` (catch `Rapid7ClientError` with `status_code is None`, set `_agents_unavailable=True`, return `0`) is preserved verbatim. The larger ceiling means we hit that path only when the console is genuinely unreachable, not just slow.

### Slice 2

```
__main__.run():
  1. resolve `enabled` per Q8 precedence (--no-progress > --progress > sys.stderr.isatty())
  2. progress = ProgressReporter(sys.stderr, enabled)
  3. for idx, check in enumerate(_REGISTRY, 1):
       progress.check_start(idx, len(_REGISTRY), check.name)
       t0 = time.monotonic()
       try:
           result = check.run(client, config)   # operational checks: no progress arg
       finally:
           progress.check_done(check.name, time.monotonic() - t0)

ConfigurationAuditCheck.run(...):
  for rule in active_rules:
      if not enabled_in_config(rule):
          progress.rule_skipped(rule.rule_name, "disabled in config")
          continue
      progress.rule_start(rule.rule_name)
      t0 = time.monotonic()
      try:
          result = rule.evaluate(snapshot, rule_config)
      finally:
          progress.rule_done(rule.rule_name, time.monotonic() - t0)
```

## Error handling

### Slice 1
- Invalid config (negative, zero, non-int): `config.py` validator raises `ConfigError` at startup (exit `3`). Tested.
- Timeout exceeded mid-run: `requests.exceptions.Timeout` is already wrapped by `client._request` into `Rapid7ClientError(status_code=None)`. `EnvSnapshot.agent_count()` already catches this and sets `_agents_unavailable=True`. **No new error path** — the larger ceiling means this fallback fires less often.
- The four other agent accessors (`agents`, `agent_asset_ids`, `agent_asset_ids_sampled`) all consult `is_agents_unavailable()` and self-skip; that contract is preserved.
- Pagination mid-stream timeout: `_paginate` raising `Rapid7ClientError(status_code=None)` propagates to the snapshot's existing try/except — same shape as today, just at the longer ceiling.

### Slice 2
- Stream write failure (broken pipe to a closed pager): `ProgressReporter` wraps each `stream.write()` in `try: ... except OSError: self._enabled = False`. First failure latches the reporter off; the run continues silently. A dead pipe must not abort an audit.
- `--progress` and `--no-progress` both passed: argparse `mutually_exclusive_group` errors at startup (exit `3`).
- Exception inside a rule's `evaluate(...)`: existing per-rule isolation in `ConfigurationAuditCheck` produces a `RuleResult(status="error", ...)`. Progress emits `rule_done(name, elapsed)` in a `finally:` block so the in-flight line always closes — operator never sees a hung `started…` with no companion `done` line. Same pattern in `__main__.py`'s check loop.

### Slice 3
- No new error paths.

## Testing

### Slice 1
- `tests/test_config.py`: `audit.agents_timeout_seconds` defaults to 180; rejects 0, negative, and non-int with `ConfigError`; unknown-key rejection still works.
- `tests/test_client.py`: `client.get(path, timeout=N)` passes `N` to `requests.request`; `client.get(path)` (no kwarg) passes `self._timeout`. Same for `client.paginate(..., timeout=N)`. Mock `requests.Session.request` and assert the `timeout=` kwarg.
- `tests/audit/test_snapshot.py`: construct snapshot with a fake client that records `kwargs` per call; assert all four `/api/3/agents` call sites pass `timeout=180` (or whatever the test config sets). Existing "agents unavailable on timeout" tests are unchanged.

### Slice 2
- `tests/test_progress.py` (new): `ProgressReporter` writes expected lines to a `StringIO`; `enabled=False` writes nothing; `OSError` on write latches `_enabled=False` and never raises; `rule_done` emits even when `rule_start` was followed by an exception (test the `finally` contract by simulating the orchestrator's call order).
- `tests/test_main.py` (or wherever CLI flag parsing is tested): `--progress` and `--no-progress` are mutually exclusive; precedence: flag wins over TTY; default = `sys.stderr.isatty()` (mock it).
- `tests/audit/test_audit_check.py`: pass a fake `ProgressReporter` with recording methods; assert `rule_start` / `rule_done` called once per active rule, in order; `rule_skipped` for disabled rules; `rule_done` called even when a rule raises.
- Existing tests that construct `ConfigurationAuditCheck` / `UserPermissionAuditCheck` without a progress arg keep working (default `None`).

### Slice 3
- `tests/test_client.py`: assert the pagination announcement is at DEBUG, not INFO (`caplog` at `DEBUG`). If no such test exists today, add a small one — protects against accidental re-promotion.

## Read-only safety review

This release adds an optional `timeout=` kwarg to `client.get` / `client.paginate` and demotes one log statement. Neither touches `_ALLOWED_VERBS` or `_ALLOWED_POST_PATHS`. Verb routing and the read-only invariant are unchanged.

`grep -nE 'PUT|PATCH|DELETE|client\.(put|patch|delete)' src/` must return zero matches before each commit, per `CLAUDE.md`.

## Release plan

Three atomic commits on `main`, then a `release: 0.3.6` commit, then the tag and runtime-zip release per `CLAUDE.md`.

Suggested commit order (any order works; this minimizes test-churn):
1. `feat(snapshot): tunable per-call timeout for /api/3/agents (default 180s)` — Slice 1.
2. `feat(progress): per-check and per-rule progress lines on stderr` — Slice 2.
3. `chore(client): demote 'Paginating …' log from INFO to DEBUG` — Slice 3.
4. `release: 0.3.6` — CHANGELOG entry, version bump, then tag + zip.

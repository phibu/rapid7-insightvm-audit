# 0.3.6 -- Agents Timeout, Progress UX, Pagination Log Demotion

Date: 2026-05-07
Target version: 0.3.6
Status: Approved (design phase)

## Summary

A bundle of three independent improvements that together polish the default-run UX and remove a known operational sharp edge:

1. **Tunable per-call timeout for `/api/3/agents`** -- the 0.3.5 incident (`read operation timed out` raised by `insight_agent_deployed` against a slow on-prem console) has a config-only fix. New field `audit.agents_timeout_seconds`, default `180`. Snapshot passes this timeout to all four `/api/3/agents` call sites; the existing "skip on timeout" safety net stays in place.
2. **Per-check / per-rule progress lines** -- new `ProgressReporter` writes structured progress to stderr, separate from the existing `logging` pipeline. TTY auto-detect by default, with `--progress` / `--no-progress` overrides.
3. **Demote `Paginating …` log line from INFO to DEBUG** -- surgical: there is exactly one `logger.info(...)` call in `client.py` today (line 227, the pagination announcement). It moves to `logger.debug(...)`. Retries / backoffs / rate-limit waits are unaffected (none of them are INFO today).

The three concerns ship as three atomic commits in one release tag.

## Motivation

The 0.3.5 final review surfaced three closely related backlog items, all rooted in the same complaint: the default-run terminal output during long audits is simultaneously noisy (pagination chatter dominates) and uninformative (no signal of which rule is currently in flight). Operators on slow on-prem consoles also get hit by a hardcoded 60s timeout on `/api/3/agents` that today silently disables every agent-aware audit rule, with no operator-facing knob to fix it.

These three items pair naturally because they all change the per-run UX without changing audit semantics: same rules, same findings, same exit codes. Bundling them avoids three separate release-train cycles for one cohesive UX improvement.

## Non-goals

Explicit out-of-scope for 0.3.6:

- **Generalized per-path timeout map.** Only `audit.agents_timeout_seconds` is added; only `/api/3/agents` reads it. If a second slow endpoint shows up later, we generalize then.
- **`progress: auto|on|off` config field.** CLI flags + TTY auto-detect only. Forward-compatible -- a config field can be added later without breaking the precedence rule.
- **Aggressive demotion of all `client.py` INFO logs.** Verified: there is exactly one `logger.info(...)` call in `client.py` today. Retries, backoffs, and rate-limit waits are not INFO.
- **Snapshot agent-head-request unification** (`agent_count()` / `agents()` / `agent_asset_ids_sampled()` each issue independent `GET /api/3/agents?size=1`). Documented in the `someday` backlog; remains there.
- **Removal of `insight_agent_version_currency` rule.** Pinned at 0.4.0; out of scope here.
- **README full refresh.** Only two README touches: one row in the threshold table for `audit.agents_timeout_seconds`, and a short mention of `--progress` / `--no-progress` in the CLI flags section.
- **`Check` Protocol signature changes.** Operational checks do not gain a `progress` parameter. Only the two audit orchestrators take a `progress: ProgressReporter | None = None` constructor arg.
- **`requests.Session` changes for timeout work.** Per-call `timeout=` kwarg only. Session-level defaults are unchanged.

## Architecture

Three independent vertical slices. No new architectural layers.

### Slice 1 -- Agents timeout

- `client.py`: thread an optional `timeout: int | None = None` kwarg through `get(path, params, *, timeout=None)` → `_request(..., timeout=None)` → `requests.request(..., timeout=timeout if timeout is not None else self._timeout)`. Default behavior unchanged when caller passes nothing.
- `client.py`: same kwarg added to `paginate(path, params, *, timeout=None)` → `_paginate(..., timeout=None)`. The per-page worker reuses the same per-call timeout. The shared `requests.Session` is unchanged; per-call `timeout=` only.
- `config.py`: new field `audit.agents_timeout_seconds: int` on the audit dataclass; default `180`; validator rejects 0, negative, and non-int with `ConfigError` (exit `3`); unknown-keys-rejection convention preserved.
- `audit/snapshot.py`: read `self._agents_timeout = audit_config.agents_timeout_seconds` in `EnvSnapshot.__init__`; pass `timeout=self._agents_timeout` to all four `/api/3/agents` call sites (today at lines 453, 486, 531, 574 -- head request in `agent_count()`, full pagination in `agent_asset_ids()`, full pagination in `agents()` when `full_scan`, sampled pagination in `agent_asset_ids_sampled()`).
- `docs/examples/config.yaml`: add the field with an inline comment pointing at the README.
- `README.md`: one new row in the threshold table.

### Slice 2 -- Progress channel

**Existing implementation (already shipped on `main`):**
- `src/rapid7_healthcheck/progress.py` exists with class `ProgressReporter` and API:
  ```
  ProgressReporter(stream: IO[str] | None = None)         # defaults to sys.stderr
  step(current: int, total: int, label: str)              # in-progress status
  done(current: int, total: int, label: str, *, duration_ms: int)  # completion
  newline_if_needed()                                     # idempotent TTY layout helper
  ```
  TTY behavior: status overwrites itself in place via `\r\x1b[K`; `done()` emits the completion + `\n`. Non-TTY: every call writes its own newline-terminated line.
- `__main__._run_checks()` already wraps each operational and audit check with `progress.step(idx, total, instance.name)` / `progress.done(idx, total, instance.name, duration_ms=...)`.
- `audit/__init__.py` (`ConfigurationAuditCheck`) and `audit/user_permission/__init__.py` (`UserPermissionAuditCheck`) already emit per-rule progress using the same `step` / `done` API with prefixed labels (`audit: <rule_id>`, `user-audit: <rule_id>`).
- `__main__.run()` constructs `ProgressReporter()` and calls `newline_if_needed()` around log output to preserve TTY layout.
- `tests/test_progress.py` covers TTY vs non-TTY, duration formatting, and `newline_if_needed()` semantics.

**Five gaps closed in 0.3.6 (the actual Slice 2 work):**
1. **CLI flags `--progress` / `--no-progress` (mutually exclusive).** Argparse `add_mutually_exclusive_group()`. Both passed → argparse exits at startup. Precedence: `--no-progress` → off, `--progress` → on, neither → `stream.isatty()` (current default).
2. **`enabled: bool | None = None` constructor arg on `ProgressReporter`.** When `enabled is None`, behavior is the current TTY-detect (no regression). When `enabled is False`, every public method is a no-op (including `newline_if_needed`). When `enabled is True`, status emits even if the stream isn't a TTY (force-on for explicit `--progress` from CI logs etc.); the non-TTY one-line-per-call format is used in that case (no `\r` overwrite into a non-TTY stream).
3. **Broken-pipe latch.** `step` / `done` / `newline_if_needed` wrap their `stream.write` + `stream.flush` calls in `try: ... except OSError: self._enabled = False`. First failure latches the reporter off; the run continues silently. A dead pager pipe must not abort an audit.
4. **`try/finally` around `step` → `done` in all three orchestrators.** Today a rule exception inside `audit/__init__.py` or `audit/user_permission/__init__.py` leaves the in-flight TTY status line un-completed (the next `step` overwrites it, but the duration is never reported). Wrap the rule call in `try: progress.step(...); rule.evaluate(...); finally: progress.done(...)`. Same pattern in `__main__._run_checks()` (which today already calls `done` after the check returns, but not via `finally` -- a check exception escapes without completing the line).
5. **`rule_skipped` emission for config-disabled rules.** When a rule is disabled in config and the orchestrator skips it, today there's no progress event at all -- the run just gets quieter. Emit a single `step(idx, total, f"<prefix>: <rule_id> (skipped)")` followed by `done(idx, total, f"<prefix>: <rule_id> (skipped)", duration_ms=0)` so the operator sees the rule was considered. (No new method on `ProgressReporter` -- the suffix conveys the state.)

The shipped class shape, label prefixes (`audit:` / `user-audit:`), and overwrite-in-place TTY behavior are **preserved**. No public-API rename, no test rewrite. Existing tests in `tests/test_progress.py` keep passing; new tests cover the five gaps.

### Slice 3 -- Log demotion

- `client.py` line 227: `logger.info(...)` → `logger.debug(...)`. One line. No other changes.

## Data flow

### Slice 1

```
config.yaml (audit.agents_timeout_seconds: 180)
   │
   ▼
config.py loads → AuditConfig.agents_timeout_seconds: int
   │
   ▼
__main__.py builds EnvSnapshot(client, audit_config)
   │
   ▼
EnvSnapshot stores self._agents_timeout = audit_config.agents_timeout_seconds
   │
   ▼
agent_count() / agents() / agent_asset_ids() / agent_asset_ids_sampled()
   call client.get("/api/3/agents", ..., timeout=self._agents_timeout)
   or  client.paginate("/api/3/agents", timeout=self._agents_timeout)
   │
   ▼
client._request(...) uses the per-call value if not None,
   else falls back to self._timeout (60s default -- unchanged for everyone else)
```

The snapshot's existing timeout-handling logic in `agent_count()` (catch `Rapid7ClientError` with `status_code is None`, set `_agents_unavailable=True`, return `0`) is preserved verbatim. The larger ceiling means we hit that path only when the console is genuinely unreachable, not just slow.

### Slice 2

```
__main__.run():
  1. resolve `enabled` from CLI flag if present, else None (auto-detect):
       if --no-progress: enabled = False
       elif --progress:  enabled = True
       else:             enabled = None   # ProgressReporter does TTY auto-detect
  2. progress = ProgressReporter(enabled=enabled)   # stream still defaults to stderr
  3. _run_checks(client, cfg, progress=progress)    # existing entry point

_run_checks(client, cfg, progress):
  for idx, instance in enumerate(active_checks, 1):
      progress.step(idx, total, instance.name)
      t0 = time.monotonic()
      try:
          result = instance.run(client, cfg)
      finally:
          progress.done(idx, total, instance.name,
                        duration_ms=int((time.monotonic() - t0) * 1000))

ConfigurationAuditCheck.run(...):
  for rule_idx, rule in enumerate(rules_to_run, 1):
      label = f"audit: {rule.rule_id}"
      if rule_disabled_in_config(rule):
          progress.step(rule_idx, total_rules, f"{label} (skipped)")
          progress.done(rule_idx, total_rules, f"{label} (skipped)", duration_ms=0)
          continue
      progress.step(rule_idx, total_rules, label)
      t0 = time.monotonic()
      try:
          result = rule.evaluate(snapshot, rule_cfg)
      finally:
          progress.done(rule_idx, total_rules, label,
                        duration_ms=int((time.monotonic() - t0) * 1000))

# UserPermissionAuditCheck identical pattern with label = f"user-audit: {rule.rule_id}".
```

Sample TTY output (status line overwrites itself; only the most recent line and prior `done()` lines remain visible):
```
[1/6] Scan Engines (1234ms)
[2/6] Scan Activity (812ms)
[3/6] Asset Coverage (4501ms)
[4/6] Data Quality (912ms)
[1/12] audit: agent_unauth_collision (1102ms)
[2/12] audit: insight_agent_deployed (42123ms)
[3/12] audit: insight_agent_version_currency (1998ms)
...
[5/6] Configuration Audit (74667ms)
[6/6] User & Permission Audit (12300ms)
```

On a non-TTY (CI / redirected stderr), `step` lines are emitted as well as `done` lines (one line per call), so the log is greppable.

## Error handling

### Slice 1
- Invalid config (negative, zero, non-int): `config.py` validator raises `ConfigError` at startup (exit `3`). Tested.
- Timeout exceeded mid-run: `requests.exceptions.Timeout` is already wrapped by `client._request` into `Rapid7ClientError(status_code=None)`. `EnvSnapshot.agent_count()` already catches this and sets `_agents_unavailable=True`. **No new error path** -- the larger ceiling means this fallback fires less often.
- The four other agent accessors (`agents`, `agent_asset_ids`, `agent_asset_ids_sampled`) all consult `is_agents_unavailable()` and self-skip; that contract is preserved.
- Pagination mid-stream timeout: `_paginate` raising `Rapid7ClientError(status_code=None)` propagates to the snapshot's existing try/except -- same shape as today, just at the longer ceiling.

### Slice 2
- Stream write failure (broken pipe to a closed pager): `ProgressReporter._write_safely(...)` (a small private helper) wraps `stream.write` + `stream.flush` in `try: ... except OSError: self._enabled = False`. First failure latches the reporter off; remaining `step` / `done` / `newline_if_needed` calls become no-ops. A dead pipe must not abort an audit.
- `--progress` and `--no-progress` both passed: argparse `add_mutually_exclusive_group()` errors at startup (exit `3`).
- Exception inside a rule's `evaluate(...)`: existing per-rule isolation in `ConfigurationAuditCheck` produces a `RuleResult(status="error", ...)`. Progress emits `done(...)` in a `finally:` block so the in-flight TTY status line always closes with a duration -- operator never sees a stale status line stuck at the failed rule. Same pattern in `_run_checks()` for whole-check exceptions.
- Config-disabled rule: orchestrator emits `step` + `done` with `(skipped)` suffix and `duration_ms=0`, then `continue`s. The skip is visible in non-TTY logs and the TTY status line briefly shows the skipped rule before the next one starts.

### Slice 3
- No new error paths.

## Testing

- `tests/test_client.py`: `client.get(path, timeout=N)` passes `N` to `requests.request`; `client.get(path)` (no kwarg) passes `self._timeout`. Same for `client.paginate(..., timeout=N)`. Mock `requests.Session.request` and assert the `timeout=` kwarg.
- `tests/audit/test_snapshot.py`: construct snapshot with a fake client that records `kwargs` per call; assert all four `/api/3/agents` call sites pass `timeout=180` (or whatever the test config sets). Existing "agents unavailable on timeout" tests are unchanged.

### Slice 2
- `tests/test_progress.py` (extend, do not rewrite): existing five tests stay green. Add tests for the new `enabled` constructor arg behavior:
  - `enabled=False`: `step`, `done`, `newline_if_needed` produce zero bytes on the stream.
  - `enabled=True` on a non-TTY stream: `step` emits one line per call (no `\r`), matching the current non-TTY behavior -- verifies that explicit on-mode doesn't try to use ANSI overwrite into a non-TTY.
  - `enabled=None` (default): behavior identical to today (covered by the existing tests; assert no regression by leaving them untouched).
  - Broken-pipe latch: a stream whose `write` raises `OSError` on the first call → first `step` swallows the error, subsequent `step`/`done`/`newline_if_needed` calls are no-ops (no second write attempted).
- `tests/test_main.py`: `--progress` and `--no-progress` are mutually exclusive (argparse exits when both passed); `--no-progress` constructs `ProgressReporter(enabled=False)`; `--progress` constructs `ProgressReporter(enabled=True)`; neither flag → `ProgressReporter(enabled=None)` (auto-detect).
- `tests/audit/test_audit_check.py` and `tests/audit/test_user_permission_orchestrator.py`: pass a recording fake `ProgressReporter` (subclass that captures `step` / `done` calls). Assert (a) `done` is called for every `step` even when the rule raises (test the `finally` contract), (b) config-disabled rules emit a `step`+`done` pair with `(skipped)` suffix and `duration_ms=0`.
- Existing tests that construct `ConfigurationAuditCheck` / `UserPermissionAuditCheck` without a progress arg keep working (the orchestrators must accept the existing `progress: ProgressReporter | None = None` constructor arg unchanged -- that parameter already exists).

### Slice 3
- `tests/test_client.py`: assert the pagination announcement is at DEBUG, not INFO (`caplog` at `DEBUG`). If no such test exists today, add a small one -- protects against accidental re-promotion.

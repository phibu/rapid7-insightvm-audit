# 0.4.0 — Remove `insight_agent_version_currency` Rule + Logging Cleanups

Date: 2026-05-07
Target version: 0.4.0
Status: Approved (design phase)

## Summary

A bundle of three independent changes, with one breaking config-shape change as the headline:

1. **Remove the `insight_agent_version_currency` audit rule** and document it as a v3 API gap. Computing agent version drift requires full pagination of `/api/3/agents` (~794 pages on an ~80k-agent fleet) — too slow for a health-check pass even with `parallel_pages=6`. The v3 API exposes no `agent-version` filter on `POST /api/3/assets/search`, no `version`/`agentVersion` field on the `Agent` schema, and no version-related query parameter on `GET /api/3/agents`. This is the only breaking change in 0.4.0 and justifies the minor-version bump.
2. **Reorder `_setup_logging` so the `file_open_error` WARNING travels through the new handlers** instead of the about-to-be-torn-down handlers from the previous pass. Cosmetically harmless today; routing is correct after the fix.
3. **Strip `FlushingFileHandler` instances from the root logger after each test** in `tests/test_logging_setup.py` and `tests/test_log_flush.py` via a small `autouse=True` fixture. Pre-emptive cleanup against handler leaks across tests; no flake observed today.

The three concerns ship as three atomic commits in one release tag, mirroring the 0.3.6 structure.

## Motivation

The `insight_agent_version_currency` rule was an early experiment that ran against the limits of Rapid7's v3 API. After three releases of refinement (0.2.0 introduction, 0.3.0 reference-version modes, 0.3.x aggregation tweaks) it became clear the rule could not reach the operational characteristics a health-check tool requires:

- Full agent fleet pagination dominates run time on consoles with tens of thousands of agents.
- The rule's findings frequently surfaced as "skipped — endpoint timed out" rather than actionable warnings.
- The user has alternative version-drift tooling outside this project's scope (CMDB, agent-management dashboards).

Removing the rule simplifies the audit catalogue and frees operators from the YAML-config block they were carrying for a rule that often skipped. The two logging-related cleanups are unrelated leftovers from the 0.3.x logging-format work; they pair well with the breaking-change moment because all three concerns are ergonomic improvements with no user-visible behavior change for healthy runs.

The stale entry will be removed from `backlog.md` after 0.4.0 ships.
- **Op-checks not threading `agents_timeout_seconds`.** Surfaced during 0.3.6 review; needs a `Check` protocol change to plumb `audit_cfg` to op-checks. Stays in `someday`.
- **README full refresh.** Slice 1 touches only the audit-rules table row (one row removed) and the existing "Rules NOT implemented (and why)" block (one bullet added). No structural changes.
- **CHANGELOG voice or structure changes.** New `0.4.0` heading follows existing format with `### Removed` plus an upgrade note.
- **No HTTP / client.py changes, no verb-allowlist edits.** Read-only invariant grep gate runs on every commit.
- **No changes to `Rule` Protocol, `_RULE_REGISTRY`, or the `register` decorator.** Only the registry contents change, via the deleted side-effect import.
- **No new fields on `AuditConfig` or `RuleConfig`.**
- **`agent_unauth_collision`, `insight_agent_deployed`, and other agent-related rule blocks** in `docs/examples/config.yaml` stay as-is.

## Architecture

Three independent vertical slices.

### Slice 1 — Remove the rule

**Files deleted:**
- `src/rapid7_healthcheck/audit/rules/insight_agent_version_currency.py` (367 LOC)
- `src/rapid7_healthcheck/audit/rules/_agent_version.py` (61 LOC, used only by the deleted rule)
- `tests/audit/rules/test_insight_agent_version_currency.py` (398 LOC)
- `tests/audit/rules/test_agent_version_parser.py` (83 LOC)

**Files modified:**
- `src/rapid7_healthcheck/audit/__init__.py:206` — drop the side-effect import.
- `src/rapid7_healthcheck/config.py:95` — drop `"insight_agent_version_currency"` from `_VALID_RULE_IDS`.
- `tests/audit/test_audit_check.py:19,30` — drop the side-effect import + the registry-expectation entry.
- `docs/examples/config.yaml:171-183` — delete the rule's config block.
- `README.md:206` — delete the audit-rules table row; add a new bullet under "Rules NOT implemented (and why)" at line 216 citing the v3 API gap (no version field on the `Agent` schema, no version filter on `GET /api/3/agents` or `POST /api/3/assets/search`). Pure API-gap framing — no removal history.

**Strict-mode behavior preserved.** A user upgrading from 0.3.6 with the old `insight_agent_version_currency:` block still in their `config.yaml` will see `ConfigError("audit.rules: unknown rule id 'insight_agent_version_currency'")` at startup (exit `3`). Documented in the CHANGELOG with the literal error message so users can grep.

### Slice 2 — Logging reorder

**File modified:** `src/rapid7_healthcheck/__main__.py:65-86` (`_setup_logging`).

Change the order from:
```
1. Build handlers list, capture file_open_error
2. logger.warning(file_open_error)              ← travels through OLD handlers
3. logging.basicConfig(force=True, handlers=...) ← OLD handlers torn down
```

To:
```
1. Build handlers list, capture file_open_error
2. logging.basicConfig(force=True, handlers=...) ← NEW handlers installed
3. logger.warning(file_open_error)              ← travels through NEW handlers
```

When `log_file=None` and no error was captured, the warn line is not emitted at all — same as today. Two-line reorder; no new abstractions.

### Slice 3 — `FlushingFileHandler` cleanup fixture

**Files modified:** `tests/test_logging_setup.py` and `tests/test_log_flush.py`.

Add an `autouse=True` fixture at the top of each file:

```python
import pytest, logging
from rapid7_healthcheck._log import FlushingFileHandler

@pytest.fixture(autouse=True)
def _strip_flushing_file_handlers_after_test():
    try:
        yield
    finally:
        root = logging.getLogger()
        for h in list(root.handlers):
            if isinstance(h, FlushingFileHandler):
                root.removeHandler(h)
                h.close()
```

The fixture is duplicated in each file (no shared `conftest.py`) — six-line duplication is cheaper than introducing a new shared module for two consumers. Conservative `isinstance(h, FlushingFileHandler)` filter only — `caplog`'s root-logger handler and any default `StreamHandler` are untouched. `h.close()` releases the underlying file descriptor so `tmp_path` cleanup doesn't race.

## Error handling

### Slice 1
- Existing `ConfigError` path reused; no new error types.
- The error message is produced by the existing `_load_audit` validator at `config.py:426` — `f"audit.rules: unknown rule id '{rule_id}'"`. The validator iterates each rule id in the user's yaml and raises on the first one not in `_VALID_RULE_IDS`, so a yaml that mentions both `insight_agent_version_currency` and other unknown rules will surface only the first one. This is consistent with existing strict-mode behavior in this codebase.

### Slice 2
- No new error paths. Reorder preserves the invariant that when `log_file=None` and no file-open error was captured, the warn line isn't emitted.

### Slice 3
- Fixture uses `try: yield; finally: <strip>` so a test exception still triggers cleanup.
- `removeHandler` is idempotent; `h.close()` on an already-closed handler is a no-op.

## Task 1 (B3): Fix `duration_ms = 0` on op-check rule cards

### Context for implementer

**Bug:** Every operational-check rule card in the HTML report shows `0ms` for its `duration_ms`, even though the check-level total is correct. User-visible regression: `Scan Activity: 19.7s` total but each of its six sub-rules reads `0ms`.

**Root cause:** `src/rapid7_healthcheck/checks/_op_rule.py` defines `safe_run` (lines 122-156). On the **error path** it computes `duration_ms` and passes it to `error_rule`. On the **success path** it does `return fn()` -- and `fn()` is a `make_rule_result(...)` call which defaults `duration_ms=0`. So timing is missing only on the success path.

**Architecture note:** `RuleResult` is a `@dataclass`. `dataclasses.replace(result, duration_ms=...)` produces a copy with the field updated. Use that -- don't mutate `result` in place (the dataclass may not be frozen but mutation is bad form, and downstream code may assume immutability).

**Why the spec chose this fix over the backlog item's per-call-site `time.monotonic()` wrapping:** the centralized fix is one edit point, automatically covers all current AND future rules, and matches the symmetry of the existing error path. The per-call-site sweep would be 20+ touched lines across 4 files.

### What to implement

Edit `src/rapid7_healthcheck/checks/_op_rule.py` `safe_run()` (the function `safe_run_rule` calls into):

```python
from dataclasses import replace
# (add to existing imports)

def safe_run(fn, *, rule_id, rule_name, description, sources=(), default_severity="warn"):
    rule_start = time.monotonic()
    try:
        result = fn()
    except Exception as e:
        logger.exception("op-check rule %s raised", rule_id)
        return error_rule(
            rule_id=rule_id,
            rule_name=rule_name,
            description=description,
            sources=sources,
            error=e,
            duration_ms=int((time.monotonic() - rule_start) * 1000),
            default_severity=default_severity,
        )
    duration_ms = int((time.monotonic() - rule_start) * 1000)
    # Preserve a non-zero duration_ms set explicitly by the rule (no current
    # rule does this, but the contract allows it -- don't clobber an override).
    if result.duration_ms == 0:
        return replace(result, duration_ms=duration_ms)
    return result
```

## Task 2 (B2): Exclude local engine from `EngineMissingLastRefreshRule`

### Context for implementer

**Bug:** `src/rapid7_healthcheck/checks/scan_engines.py:149-181` (`EngineMissingLastRefreshRule`) flags engines with no `lastRefreshedDate`. The local scan engine (default name `"Local scan engine"`, in-process) never has one by design. Result: every InsightVM deployment reports a false warning for its local engine.

**Existing predicate:** `src/rapid7_healthcheck/audit/rules/local_engine_production_scope.py:19` defines `_is_local_engine(engine, extra_names)`. We'll extract it to a shared top-level module so both verticals can use it without `checks/` depending on `audit/`.

**Why extract rather than copy-paste:** keeps the two call sites in lock-step. If a future Rapid7 release changes how the local engine is reported, one fix covers both.

### What to implement

**Step 1: extract the helper.**

Create `src/rapid7_healthcheck/_local_engine.py`:

```python
"""Shared heuristic for identifying the console-co-located local scan engine.

Used by both the operational scan-engines check and the configuration
audit (local_engine_production_scope rule). v3 ScanEngine has no
first-class local/distributed flag, so we detect by loopback address or
the default name Rapid7 ships.
"""
from __future__ import annotations

_LOOPBACK_ADDRESSES = {"localhost", "127.0.0.1", "::1"}
_DEFAULT_LOCAL_NAMES = {"local scan engine"}


def is_local_engine(engine: dict, extra_names: set[str] | None = None) -> bool:
    """Return True if `engine` is the console-local scan engine.

    Detects either a loopback address or the default name. `extra_names`
    is for audit rules that thread an operator-overridden name list
    (lower-cased) from their `rule_config`; pass None when no override
    is available (op-check rules today do not receive `rule_config`).
    """
    addr = (engine.get("address") or "").strip().lower()
    if addr in _LOOPBACK_ADDRESSES:
        return True
    name = (engine.get("name") or "").strip().lower()
    if name in _DEFAULT_LOCAL_NAMES:
        return True
    if extra_names and name in extra_names:
        return True
    return False
```

## Task 3 (B1): `EngineUnpairedRule` honors scan engine pools

## Task 4 (B4): Verify single_engine_overload fallback (no code change)

### Context for implementer

**Concern from backlog:** `audit/rules/single_engine_overload.py:43` has a `f"id={engine_id}"` fallback for unknown engines. The backlog item asks whether B1's pool fix makes this fallback reachable.

**Spec verdict:** B1 does **not** add pool-assigned engines to `single_engine_overload`'s `sites_by_engine` index -- that rule iterates `snapshot.sites()` and reads `site["scanEngine"]` (direct only). So:
- `sites_by_engine` keys are always direct-assigned engine IDs from existing sites
- `engines_by_id` is keyed by every engine in `scan_engines()`

```python
# Defensive fallback: a site's scanEngine ID should always exist in
# /api/3/scan_engines. Keep the fallback as a safety net for the
# pathological case where the console returns inconsistent data.
```

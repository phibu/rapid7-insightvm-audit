# 0.3.0 — Op-check rule isolation + class-shaped rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert all 14 op-check rules across `scan_engines.py`, `scan_activity.py`, `asset_coverage.py`, `data_quality.py` to standalone classes with class-level identity constants (`RULE_ID`, `RULE_NAME`, `DESCRIPTION`, `DEFAULT_SEVERITY`, `SOURCES`). Extend per-rule isolation to the two checks that don't have it yet.

**Architecture:** Each rule becomes a class with class-level identity attributes plus a `run(...)` method returning a `RuleResult`. A new `safe_run_rule(rule, fn)` helper in `_op_rule.py` reads the class attributes and dispatches to the existing `safe_run`. Each `Check.run()` shrinks to: do I/O once, instantiate rule classes, dispatch each via `safe_run_rule`, build the `CheckResult`. No HTTP changes, no new endpoints, no behavior change.

**Tech Stack:** Python 3.11+, pytest, stdlib only (`typing.NamedTuple`, `dataclasses.dataclass(frozen=True)`).

**Companion spec:** `docs/superpowers/specs/2026-05-06-0.3.0-op-check-rule-classes-design.md`

def safe_run_rule(rule, fn: Callable[[], RuleResult]) -> RuleResult:
    """Run a rule's producer, reading identity from the rule's class attributes.

    Convenience wrapper over `safe_run` for rule classes that declare their
    identity as `RULE_ID`, `RULE_NAME`, `DESCRIPTION`, `DEFAULT_SEVERITY`,
    `SOURCES` class attributes. The helper preserves `safe_run`'s contract:
    on any exception in `fn`, returns an `error_rule` keyed on the rule's
    identity instead of propagating.
    """
    return safe_run(
        fn,
        rule_id=rule.RULE_ID,
        rule_name=rule.RULE_NAME,
        description=rule.DESCRIPTION,
        sources=rule.SOURCES,
        default_severity=rule.DEFAULT_SEVERITY,
    )
```

def _collect_duplicate_groups(client, t) -> tuple[list[dict], list[dict]]:
    """Single paginate over /api/3/assets, returning host- and IP-keyed duplicate groups.

    Returns ``(host_groups, ip_groups)`` where each list element is a dict with
    ``key``, ``ids``, ``count`` keys. Groups with count <= 1 are dropped.
    Either list may be empty if the corresponding flag (``flag_duplicate_hostnames``
    / ``flag_duplicate_ips``) is False — the caller still receives an empty list,
    not None.
    """
    by_host: dict[str, list[dict]] = defaultdict(list)
    by_ip: dict[str, list[dict]] = defaultdict(list)
    if not (t.flag_duplicate_hostnames or t.flag_duplicate_ips):
        return [], []
    for asset in client.paginate("/api/3/assets"):
        if t.flag_duplicate_hostnames:
            host = (asset.get("hostName") or "").strip().lower()
            if host:
                by_host[host].append(asset)
        if t.flag_duplicate_ips:
            ip = (asset.get("ip") or "").strip()
            if ip:
                by_ip[ip].append(asset)
    host_groups = [
        {"key": k, "ids": [a.get("id") for a in assets], "count": len(assets)}
        for k, assets in by_host.items()
        if len(assets) > 1
    ] if t.flag_duplicate_hostnames else []
    ip_groups = [
        {"key": k, "ids": [a.get("id") for a in assets], "count": len(assets)}
        for k, assets in by_ip.items()
        if len(assets) > 1
    ] if t.flag_duplicate_ips else []
    return host_groups, ip_groups
```

```python
def _compute_engine_count_summary(engines: list[dict], rule_results: list[RuleResult]) -> dict:
    """Derive per-engine worst-severity counts from rule-emitted findings.

    Walks every rule's findings, extracts the engine_id from finding.details
    (via either the "id" or "engine_id" key — different rule classes use
    slightly different details shapes), and tracks the worst severity seen
    per engine. Engines that appear in no finding are healthy.
    """
    SEV_RANK = {"info": 0, "warn": 1, "fail": 2}
    worst_per_engine: dict[object, str] = {}
    for r in rule_results:
        for f in r.findings:
            details = f.details or {}
            engine_id = details.get("id") if "id" in details else details.get("engine_id")
            if engine_id is None:
                continue
            current = worst_per_engine.get(engine_id)
            if current is None or SEV_RANK[f.severity] > SEV_RANK[current]:
                worst_per_engine[engine_id] = f.severity
    total = len(engines)
    fail_count = sum(1 for s in worst_per_engine.values() if s == "fail")
    warn_count = sum(1 for s in worst_per_engine.values() if s == "warn")
    healthy = total - fail_count - warn_count
    return {
        "engines_total": total,
        "engines_healthy": healthy,
        "engines_warn": warn_count,
        "engines_fail": fail_count,
    }
```

**Detail-key compatibility**: existing finding details use `"id"` for the bad-status / last-contact / missing-refresh branches and a richer dict for unpaired (also keyed `"id"`). Verify all four rule classes write `"id"` (or `"engine_id"`) in their finding details — the helper looks for either.

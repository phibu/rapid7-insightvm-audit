## Task 1 (F1): Scaffold the `template_audit` vertical

### Context for implementer

InsightVM scan templates have 50+ tunable settings; misconfiguration produces wrong scan results silently. This release adds a 4th audit vertical (Template Configuration Audit) parallel to Configuration / User & Permission / Cloud Drift. The scaffold is the load-bearing piece -- F2-F4 implementer tasks add rules to the registry you wire up here.

**Pattern to mirror.** The User & Permission Audit (`audit/user_permission/`) is the cleanest existing example: registry pattern, decorator, orchestrator, config dataclass, side-effect imports, validation. Read it end-to-end before starting. The Cloud Drift Audit is the second example -- similar pattern but with two clients. You're mirroring the User & Permission shape, not Cloud Drift (no second client needed).

### What to implement

#### 1. Snapshot accessor

`src/rapid7_healthcheck/audit/snapshot.py` -- add new accessor near existing `scan_template(id)` (around line 418):

```python
def templates_full(self) -> list[dict]:
    """Return all scan templates from /api/3/scan_templates with full
    nested settings (checks, discovery, web, policy, database, telnet).

    Paginated per v3 spec. Cached on first call. Each item is the full
    ScanTemplate envelope per the v3 OpenAPI schema.

    Distinct from `scan_template(id)`, which fetches a single template
    by ID for callers that already know the ID -- template_audit rules
    walk the full list and benefit from one paginated fetch.
    """
    if self._templates_full is None:
        self._templates_full = list(self._client.paginate("/api/3/scan_templates"))
    return self._templates_full
```

Init field: `self._templates_full: list[dict] | None = None` in `__init__` (near `self._scan_templates`).

## Task 2 (F2): Vuln-check + policy correctness rules (7 rules)

### Context

F1 wired up the empty vertical. Now implement the first 7 rules -- all focus on vulnerability-assessment correctness (template runs but produces zero/wrong results).

### Pattern to mirror

Each rule is a self-contained file under `src/rapid7_healthcheck/audit/template/rules/`. The User & Permission Audit rules under `audit/user_permission/rules/` are the canonical mirror -- read 2-3 of them to internalize the pattern (recommendation: `locked_user_account.py` is simple, `privileged_user_without_mfa.py` is complex with skip branches).

Each rule:
- Self-registers via `@register_template_rule` decorator
- Declares `rule_id`, `rule_name`, `description`, `default_severity`, `expensive`, `sources` class attributes
- `run(self, snapshot, severity, full_scan, sample_size, rule_config) -> RuleResult` method
- Builds a `RuleResult(...)` directly (audit rules don't use `make_rule_result`)
- Populates `card_summary={"examined": N, "passed": max(0, N - failed), "failed": failed}` per 0.7.0 contract -- for rules where "examined" is genuinely ambiguous, leave None
- Reads templates via `snapshot.templates_full()`

### Per-rule disposition table for F2

| Rule | Severity | Examined denominator | Failed numerator |
|------|----------|----------------------|------------------|
| `vuln_enabled_but_no_checks` | fail | count of vuln-enabled templates | count of those with no checks |
| `potential_checks_disabled` | warn | vuln-enabled count | count with `potential: false` |
| `correlate_disabled` | warn | vuln-enabled count | count with `correlate: false` |
| `unsafe_checks_disabled` | info | vuln-enabled count | count with `unsafe: false` (info -- doesn't escalate) |
| `disabled_checks_in_individual_overrides` | warn | total templates | count exceeding threshold |
| `policy_enabled_but_no_policies_selected` | fail | policy-enabled count | count with `policy.enabled: []` |
| `policy_only_template_attached_to_vuln_site` | info | count of policy-only templates | count bound to a high-importance site |

### What to implement per rule

For each rule:

1. **Create file** `src/rapid7_healthcheck/audit/template/rules/<rule_name>.py`
2. **Import** `register_template_rule` from `..__init__`, `RuleResult` from `rapid7_healthcheck.audit`, `Finding` from `rapid7_healthcheck.checks`
3. **Define class** decorated with `@register_template_rule`
4. **Source URL** -- use a Rapid7 docs URL for each rule (suggested: `https://docs.rapid7.com/insightvm/scan-templates/`). Don't invent URLs -- use that base for all rules in this audit.
5. **`run()` body** -- walk `snapshot.templates_full()`, apply predicate, build findings with severity from the `severity` parameter (or hardcoded for hard-fail rules like `vuln_enabled_but_no_checks`).
6. **`card_summary`** -- set per the table; `examined` is the rule-specific population (vuln-enabled count for most), not total templates.
7. **Append to `audit/template/rules/__init__.py`** side-effect import block (alphabetical).
8. **Append rule_id to `_VALID_TEMPLATE_AUDIT_RULE_IDS`** in `config.py`.
9. **Add entry to `docs/examples/config.yaml`** under `template_audit.rules:` with default severity + any knob.

### Per-rule details

#### `vuln_enabled_but_no_checks`
- `rule_id = "template.vuln_enabled_but_no_checks"`
- `default_severity = "fail"`
- Predicate: `t.get("vulnerabilityEnabled")` AND empty `t.checks.types.enabled` AND empty `t.checks.categories.enabled`
- Defensive: every nested access uses `(... or {}).get(...) or []` -- templates may have partial bodies
- Finding details: `template_id`, `template_name`
- Test cases: vuln-enabled with empty checks → flagged; vuln-enabled with categories → not flagged; vuln-enabled with types → not flagged; vuln-disabled → not flagged.

#### `potential_checks_disabled`
- `rule_id = "template.potential_checks_disabled"`
- `default_severity = "warn"`
- Predicate: `vulnerabilityEnabled: true` AND `checks.potential is False` (exactly False, not falsy -- be precise; missing is fine since the default is True per spec)
- Test: vuln-enabled with `checks.potential: false` → flagged; with `checks.potential: true` → not flagged; with no `potential` key → not flagged (default True).

#### `correlate_disabled`
- `rule_id = "template.correlate_disabled"`
- `default_severity = "warn"`
- Mirrors `potential_checks_disabled` exactly with `checks.correlate is False`.

#### `unsafe_checks_disabled`
- `rule_id = "template.unsafe_checks_disabled"`
- `default_severity = "info"` -- **important: info doesn't escalate check status** per CLAUDE.md docs. The check stays `pass` even with findings. This is intentional.
- Predicate: `checks.unsafe is False`.
- Test: confirm severity stays info even when the rule_config tries to override to fail (info-only override is allowed but check-status escalation rules don't escalate on info -- verify the existing `_rollup_audit_status` behavior).

#### `disabled_checks_in_individual_overrides`
- `rule_id = "template.disabled_checks_in_individual_overrides"`
- `default_severity = "warn"`
- Knob: `max_disabled_individual_checks` (int, default 20). Read via `int(rule_config.get("max_disabled_individual_checks", 20))`. Use `max(1, ...)` guard.
- Predicate: `len(t.checks.individual.disabled or []) > threshold`
- Examined: all templates (not just vuln-enabled -- individual overrides apply across types). Failed: count exceeding threshold.

#### `policy_enabled_but_no_policies_selected`
- `rule_id = "template.policy_enabled_but_no_policies_selected"`
- `default_severity = "fail"`
- Predicate: `policyEnabled: true` AND `len(t.policy.enabled or []) == 0`
- Test: policy-enabled with empty list → flagged; with one policy → not flagged; with no `policy` key → flagged (missing policy block with policyEnabled:true is the same shape bug).

#### `policy_only_template_attached_to_vuln_site`
- `rule_id = "template.policy_only_template_attached_to_vuln_site"`
- `default_severity = "info"` (or warn -- implementer's call; default info per spec)
- Predicate: `vulnerabilityEnabled: false AND policyEnabled: true` AND any site with `EnvSnapshot.site_scan_template_id(site) == template_id` has `site.importance in {"high", "very_high"}`
- Use the existing `EnvSnapshot.site_scan_template_id(site)` helper from `audit/snapshot.py` for the dual-shape site.scanTemplate handling.
- Cross-reference uses `snapshot.sites()`.
- Examined: count of policy-only templates. Failed: count of those with at least one high-importance site binding.

### Tests per rule

For each rule, ~3-4 tests:
- Happy path: predicate matches → finding emitted with expected severity and details
- Negative path: predicate doesn't match → no finding
- Edge cases per rule (missing keys, empty arrays, etc.)
- `card_summary` assertion (one per rule -- confirms it's populated correctly)

## Task 3 (F3): Discovery / web spider / database / telnet rules (6 rules)

### Per-rule disposition

| Rule | Severity | Examined | Failed |
|------|----------|----------|--------|
| `service_discovery_disabled` | warn | vuln-enabled count | count with empty `discovery.asset.tcpPorts` AND `udpPorts` |
| `web_spider_enabled_no_targets` | warn | webEnabled count | count with no targets configured |
| `web_spider_credentials_missing` | warn | webEnabled count | count where bound sites lack http-form/http-headers creds |
| `database_targets_no_db_credentials` | warn | count of templates with DB targets | count where bound sites lack matching DB creds |
| `telnet_regex_unset` | info | total templates | count with all 4 telnet regex fields empty |
| `telnet_regex_invalid` | warn | count with any non-empty regex | count where any regex fails `re.compile()` |

### Special considerations

- `web_spider_enabled_no_targets` -- the `web` object is freeform per spec. Defensively check `web.includedPaths` AND `web.startPaths` AND `web.discoveryEnabled`. If the schema doesn't match at all (e.g. `web` is None), the rule doesn't flag (skip). Don't emit an error rule -- just don't flag.
- `web_spider_credentials_missing` and `database_targets_no_db_credentials` -- both cross-reference sites + site_credentials. Use `EnvSnapshot.site_scan_template_id(site)` to find sites using each template. For credential type matching, use `account.get("service")` defensively (SharedCredential.account is a nested object per spec).
- `telnet_regex_invalid` -- wrap `re.compile()` in try/except; catch `re.error`.

### Workflow

Same as F2 -- one rule file per rule, one test file per rule. Append imports to `audit/template/rules/__init__.py`. Append rule_ids to `_VALID_TEMPLATE_AUDIT_RULE_IDS`. Append config entries to `config.yaml`.

## Task 4 (F4): Hygiene + inventory rules (4 rules)

### Per-rule disposition

| Rule | Severity | Examined | Failed |
|------|----------|----------|--------|
| `template_inventory_summary` | info | total templates | always 0 -- pure informational |
| `parallel_assets_extreme` | info | total templates | count outside [min, max] |
| `enhanced_logging_in_prod` | info | total templates | count of (enhancedLogging:true, bound to high-importance site) |
| `near_duplicate_templates` | info | total templates (or 0 if skipped) | count of templates with a near-duplicate |

### Special considerations

- `template_inventory_summary` -- always-passes informational rule. Emits ZERO findings; populates `summary` with counts (total/vuln_enabled/policy_enabled/discovery_only). `card_summary={"examined": total, "passed": total, "failed": 0}`. Status: `pass`.

- `parallel_assets_extreme` -- knobs: `parallel_assets_min` (default 2), `parallel_assets_max` (default 50). Both validated with `max(1, int(...))` for min and `max(min, int(...))` for max.

- `enhanced_logging_in_prod` -- cross-reference: for each template with `enhancedLogging: true`, find sites using it, check `site.importance in {"high", "very_high"}`.

- `near_duplicate_templates` -- O(N²). **Cap**: if `len(templates) > sample_size`, emit a single info finding "skipped because N templates exceeds sample_size threshold; rerun with `audit.full_scan: true` for full pairwise check" and return early. Otherwise: compute pairwise similarity via the helper in the spec. Threshold knob: `similarity_threshold` (float, default 0.95). Findings: one per cluster of near-duplicates (not one per pair -- group templates by signature first to avoid combinatorial finding count).

### Workflow

Same as F2/F3 -- one rule file per rule, one test file per rule.

### Commit message

```
feat(template-audit): hygiene + inventory rules (F4)

Four rules covering template hygiene and inventory:

- template.template_inventory_summary (info): always-pass, populates
  template counts in summary
- template.parallel_assets_extreme (info): maxParallelAssets outside
  configurable bounds (default 2-50)
- template.enhanced_logging_in_prod (info): debug logging on
  high-importance site binding
- template.near_duplicate_templates (info): ≥95% identical settings;
  skips when len(templates) > sample_size (O(N²))

near_duplicate_templates uses a top-level-field similarity heuristic
(JSON-canonical signature, ignoring id/links/name). Cluster-based
finding emission (one finding per duplicate cluster, not per pair)
keeps the report tractable.
```
